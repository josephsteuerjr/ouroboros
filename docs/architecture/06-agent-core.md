# 6. Agent Core

Agent lifecycle, tools, context fitting, authority, reviews, delegated custody and activity, planning, reflection, memory, focus, skills and budgets. Pooled tasks and direct turns, wakes included, run in `OuroborosAgent`'s `loop.py`; review and post-task executors settle separately. The decision that shapes the chapter: admission, execution, objective, review, artifact and custody are typed axes never converted into one another, so a missing or unverified answer reads as a gap, never as a verdict; code records, fences and discloses, the model judges.

### Task lifecycle

Queued tasks reach `OuroborosAgent` through the supervisor queue (§5); a direct-chat turn runs its own in-process agent with a process-local `DirectActivityRegistry` entry and no `PENDING`/`RUNNING` row (§3). The root pipeline (`agent_task_pipeline.py`) freezes the task contract and the immutable context core, runs the loop, stores the result (`task_results/<id>.json`; schema admission is `task_result_schema.py`'s: §11) and its artifacts, runs the root-only post-task work (`post_task_synthesis.py`, checkpointed by `post_task_checkpoint.py`) and publishes the typed outcome. Queue admission proves durable acceptance only; completion, objective satisfaction, artifact finality, verification and review acceptance are separate axes. Cost and token fields on the result are the usage ledger's answer (`supervisor/state.reconstruct_task_cost`), the loop's own tally rides `loop_outcome.usage`; a crash is `failure.kind = "runtime"`, never a fabricated provider failure, and a capture the crash lost reads unknown, never zero.

Timing facts are telemetry, never gates: `finalization_timing.py` carries the finalization phases on the live final event plus one `task_finalization_timing` row after the sender returns. Sender return proves no client display; replay gaps stay unknown. `supervisor/cognitive_operations.py` leases in-flight LLM, review, VLM and tool work as typed `cognitive_operation` facts for the idle rail, so a typed in-flight call is not idleness; deadlines, budgets, cancellation and absolute ceilings remain independent axes.

Within one loop the transcript is append-only: each send extends the previous one, because OpenAI-family caches reuse a request only when it is a byte-prefix of the next (inside the leading system unit a byte-prefix is necessary, not sufficient: §6 Prompt caching), so a replaced tail or a rewritten earlier message discards the whole conversation cache. `transcript_prefix.py` records every break as `prompt_prefix_break` and never blocks; deliberate compaction seams identify themselves through `sanction_rewrite`.

`model_execution` is a compact projection of the last ordinary solve response the loop accepted (text or tool calls), chosen from marked `llm_call_refs`; it keeps the requested model and local route, the route used and the provider's own label separate, and empty responses, forced finalization, review and post-task calls cannot replace it. A host-driven model change after tool work is an authoring handover: the successor's first tool-less response gets one recovery round, a second yields `execution=degraded` with `authoring_handover_incomplete`; explicit model changes and ordinary no-tool turns are exempt.

`DeliveryCandidate` is retained before verification or review, so a later notice, reviewer failure, deadline or provider outage cannot erase a useful answer. `outcomes.py` combines the execution, objective, review, artifact, child-absorption and custody axes (`outcomes.custody_debt_axes`) without converting one into another; verify-before-done receipts and exact artifact references are host-attested evidence, declarations and answer prose are not. Failed tool calls alone do not degrade a delivered answer (`residual_tool_errors_without_review` warns when the objective is `not_evaluated`). Host acceptance or an informed Advisory author finish establishes objective success; a forced exit publishes the best current candidate only with its typed rail, and lifecycle may read `completed` while the objective or review axis records a best-effort or unaccepted result. A `FINAL ANSWER:` line is latched every round as the latest typed candidate, so review, nudge and forced-finalization paths never erase a structured answer; the marker is prompted only under `task_contract.answer_protocol="final_answer_line"`, the latch stays unconditional. The stored `reason_code` is never rewritten: custody debt heals from the write side, and the owner-facing Reason line resolves at render time with each standing limitation worded beside the rail cause, never over it (§3 Task cards, errors and reason lines).

Host plan/orphan disclosures ride beside the model answer as `terminal_host_notice`, a result field; delivery sends the answer alone, and the custody audit is its own typed row (`terminal_custody_notice` → `system_type="custody_notice"`), so the open-delegation fact never enters the assistant text; CLI gets one host-labelled status (`terminal_host_notice_text`), and external Presence speech excludes host notices. Answer bytes do not change: the answer keeps its hash and its real PASS or FAIL when only a notice changes, and equal text cannot revive a superseded verdict. Every reader that hands a result on carries the notice as a separate field, and child-result and plan-evidence hashes include it, so a changed child limitation invalidates an old parent disposition or review. A host-salvaged terminal is labelled, never hidden: its durable row carries `Preserved intermediate output (not a final answer):` with a bounded excerpt, while `get_task_result` and the stop receipt keep the untruncated copy.

`loop_delivery.py` owns the task-local completion request and the retained `DeliveryCandidate`. A first reply or a direct follow-up without a selection episode is a plain final. After a substantive host continuation Main selects via `finish_task(action="finish"|"stop", answer=...|answer_sha256=...)`: full bytes, or the hash of a retained or whole held response, regardless of length; held bytes live in the canonical transcript, and compaction withdraws the selectors it made unavailable. A Presence send completes in one batch only with host-confirmed delivery; a failed or uncertain send proves none. Non-speaking children gain local completion without raising their signed resource ceilings.

Finish keeps its child, skill/handover, owner-source, material, service, configured-review and admission checks. Stop names unfinished work, buys no critic or replacement answer, cancels no descendants and retains the selected bytes; Stop/Panic, exhausted money, deadline and provider failures keep their own causes, and evidence-only changes cannot undo a stop. Completion and criticism stay separate: `previous_revision_accepted` keeps the reviewed and the delivered hash distinct. Undispositioned direct children hold finish; reminders never force completion and explicit stop stays available. Child custody debt is visibility, not root-patch authority or a verdict (DESIGN §4 Status and chips).

Provider death is the forced rail that is not best-effort completion: it salvages the best text but stamps `infra_failed`, so the task ends `failed` with reason `provider_unavailable` (`resource_refusal_no_resend` for a typed temporary refusal) and an immediate owner notification that the task was not completed. Its one forced model call runs only while a call can land: wait expiry and the no-call sources of `loop_llm_call.provider_no_call_source` (the `<cause>_no_resend` family) forbid a resend, so no second retry window is paid over a proven-dead provider. Terminal delivery preserves producer authorship: `terminal_provider_notice` is host presentation beside the raw result and quotes only the provider's own words (`loop_transport.stamp_owner_provider_message`); receipts and System incidents carry the unknown-outcome warning and never recommend a blind rerun. Every forced rail stamps one producer word at the single forced-finalization sink: `model_final` for complete model text, `host_notice` for host-written terminal text (an owner System row, never automatic Presence speech), and `host_salvage` only on the provider-death rail, where delivery shows the outage receipt and the full bytes stay in task details.

Finalization controls are typed owner-mailbox entries, not injected owner prose: the supervisor may request one bounded tool-less answer, salvage the last persisted assistant text and retain a full canonical copy when a preview would truncate it; descendant activity is not the task's own progress. An unkillable process stays visibly running, and custody checks keep another runtime instance from reaping work it does not own. Cancellation can retain live `delegated_runs_unreconciled` beside a zero, final ledger cost projection; cost finality does not prove custody settlement.

#### Task acceptance

**Purpose and eligibility.** Task acceptance grades evidence and advises useful authorized work, separately from the P3 commit gate (`triad_review.TIER_CLASSIFICATION_RULES`): partial delivery does not close the goal, and a sufficient result needs no embellishment. In `auto`/`required` the panel reviews observable effects, typed deliverables and criteria and explicit root nominations, research included; queue membership alone qualifies only in `required`, ordinary conversation, exploration or memory updates alone do not qualify in `auto`, and a child gets no automatic review (`skipped_child_advisory`). No prose or tool-count classifier decides (P5). `acceptance_history.py` freezes the answer, criteria, owner inputs and retained host refs of roots and retries that skipped a panel; uncaptured bytes stay gaps, never current-file reconstructions.

**Late review.** `task_acceptance_review(late_review=...)` needs a new owner chat, quiz or mailbox `owner_source`. `amend_cap` only sets an absolute original-root cap, with no review; `review` runs the full `acceptance_late` pool wave on frozen terminal roots and retries, even with review mode off. Caps bind on known original-root/group spend, successors included and holds disclosed beside it; Stop, Panic, prohibitions and calendar bounds bind; Hurry/Wrapup block only unstarted automatic work. A new automatic panel needs calendar headroom above the acceptance floor; a paid or unknown replay is collection-only (`review_operation.prepare_historical_operation`).

**Nomination and settlement.** `task_acceptance_review` nominates the result (`deferred_to_host_acceptance`, `authoritative=false`); Main authors the criteria. `acceptance_settlement.announce_acceptance_settlement` mails each reviewer's own verdict, never an aggregate, at quorum and at final settlement; any mail wakes a wait, but only the typed owner/control drain captures sources, acknowledges and seals, and system, descendant, independent-task or peer mail grants no owner revision. Pending final deliveries wait unless the mode permits finishing (Blocking waits; Cyber Pro: Main decides; Advisory: `pending_review`). Without re-nomination a text-only PASS rewrite may reuse approval (`previous_revision_accepted`, disclosed, no commit/plan/skill authority) only when owner source, criteria and material evidence match. Acceptance's sole publisher, `acceptance_settlement.settle_acceptance_operation`, enqueues one System `card_row="reviews"` row through the canonical outbox; failed publication announces nothing and keeps `unpublished` duty across controller exit. Late evidence keeps settlement time and the reviewed identity (`reviewed_revision=delivered|different|unknown`); version precedes verdict, and settlement grants no continuation.

**Already-paid operations.** `review_operation.ReviewOperation` (`review_custody.run_custodied_review_slots`) owns the shared wait, quota clocks and controls, so a panel released at the dispatch barrier outlives the author turn that bought it; read-back `review_operations` binds ids, controller, immutable request and original-root paid authority before any send. Recovery verifies claimant, binding and paid identity and preserves immutable sources. `collect_recorded_acceptance_run` parses locally and never calls a model; worker death is unknown, never a resend. Cold model, profile and harness facts come from `final_attempt_facts` (§6 Session identity).

**Evidence capture.** `repo_diff_capture.capture_repo_diff` feeds both the bounded preview and the exact source from one read, so the two views describe one tree. A failed, cut or undecodable capture is a gap, never a clean tree; a partial preview without its capture is `repo_diff_capture_missing`, never reconstructed from the current tree. Exact bytes stay private in observability CAS (`retain_private_capture`); the packet, `repo_diff_source_ref` and owner views get text redacted per whole section before any cut, and stderr, exceptions and bound-cut sections are withheld publicly because they may end inside secrets.

**Preparation identity and incidents.** `acceptance_preparation.preparation_source_identity` binds a local pre-binding failure to the material it would have reviewed, not to its exception text, so two exceptions over unchanged material are one incident. Changed material or criteria reopens preparation; otherwise one more attempt needs the exposed current failure plus an explicit source-bound `acceptance_retry` (`material_change|repair_evidence|owner_retry`), and spent sources grant nothing again. A failed evidence read is unknown, never a silent PASS: the answer stays one candidate, keep allowed but unverified (`evidence_current=false`), and unknown rebinding revokes approval. Local incidents carry `origin=local_acceptance_preparation`, never invented findings; `derive_loop_outcome` leaves an unresolved preparation terminal unfinished in Blocking and best-effort in Advisory.

**Admission fence and packet.** Before review, `supervisor/queue_transitions.py` closes child admission under `_queue_lock` and `task_status.find_child_tasks` proves subtree quiescence; an unanswered fence buys no model round (§10 invariant 25), and final delivery seals again through `loop_delivery._seal_admission_before_delivery`. The canonical `budget_drive_root` packet keeps verbatim owner directives, contract and criteria, deliverable identity, terminal children, verification receipts, artifact refs and `omissions_manifest`; shedding is disclosed and ordered, retains `repo_diff_source_ref`, and marks exhaustion `__immutable_core_overflow__`. `reviewer_slot_config.review_pool_slots` preserves the three deliveries: packet rows get assembled evidence, sessions the full packet, native rows inspect `native_data_root` (`host_observed`) under `acceptance_retrieving_work_order`; refs resolve against the full packet, never the render (§10). `review_source_closure.retain_review_request_sources` retains every named source snapshot under `source_handles/review_inputs/<request>/` before any paid binding; missing or corrupt bytes refuse before payment. An oversize first send becomes a compact work order with exact packet keys; changed session bytes yield `degraded_source_unreachable`, and a harness refusal stays a gap.

**Pricing and paid identity.** A child call selects at most one configured `reviewer_slot_id` (implicit when sole); root `off` disables automatic review, explicit calls use the full configured advisory panel. Wave admission estimates one API first send per row (sessions unpriced, no rounds multiplier) as disclosure; only known spend already at a limit refuses, as `review_wave_budget_insufficient`. Paid identity (`acceptance_paid_identity`) binds the semantic subject plus substantive obligation dispositions; forensic hashes and ingress counters alone buy no panel. A resubmit with the same paid identity replays its recorded verdict free: a clean replay can authorize acceptance, a non-clean one keeps its verdict and `identical_acceptance_refused`.

**Quorum and verdicts.** Pool seats are independent actors under adaptive quorum (`review_model_routes.adaptive_quorum`, re-exported by `config`: 2-of-N for N≥3, both for N=2, one reviewer as a loud `single_reviewer_no_diversity`; too few responses stay a loud infra quorum failure), retrieving verdicts equally authoritative. Transport, parse, verdict, criterion support, route and binding hashes stay distinct, so an unavailable or malformed response never masquerades as a negative judgment; a panel refused before transport is `not_dispatched` on every row. `PASS`/`FAIL`/`DEGRADED` are reviewer verdicts; only `loop_acceptance._set_acceptance_decision` writes the host decision (`accepted`, `revision_requested`, `finalized_unaccepted`). A clean quorum supplies critic approval; an Advisory author finish is author authority, never a host tier; neither changes the original verdict. A no-quorum outcome keeps minority findings as partial feedback, and a terminal technical failure keeps `reason=review_degraded` when no permitted author completion follows.

**Criteria, obligations and author stance.** A clean criterion is evidence-resolved, not merely well argued: reviewer `evidence_refs` must be exact members of the full packet's enumerable reference vocabulary, and a claim id resolves only through `acceptance_support_refs` linked to a passing host receipt. An unresolved reference keeps the actor's audit record but loses its clean contribution (`criteria_refs_unresolved`); this total, fail-closed resolver is why a task cannot certify itself by echoing its expected outcome. Actionable findings enter the durable obligation dialogue with stable identity: repair the means with requirement evidence, rebut error or inapplicability, or ask reviewers to declare stable disagreement; a valid rebuttal retires the row, an invalid one reopens it with both positions kept, and each panel reads the bounded `acceptance_dialogue_history` outside the hashed evidence material, so reading history mints no fresh paid binding. Every outcome permits author inspection, correction or rebuttal: `author_action=finish` binds to feedback exposed in Main's responding request, `stop` retains unfinished work without approval, an informed Advisory finish is permitted after criticism or unavailability (author hash and critic hash stay separate), and Blocking needs fresh reviewer approval for disputed advancement, never an automatic root or budget reset. `dialogue_status` preserves reviewer positions and never chooses the author's stop. Cyber keeps BIBLE P0/P3 authority without rewriting verdict, cost or custody.

**Pacing and the paid stamp.** `task_pacing.review_launch_allowed` admits a new critic only with cycle capacity, the wallet admission above and more than `OUROBOROS_ACCEPTANCE_REVIEW_EST_SEC` above the finalization reserve; the floor predicts no duration and applies once, at loop admission before the evidence build (`review_skipped_deadline_reserve`). `improvement_pass_allowed` has no reviewer floor (`improvement_window_inside_reserve`). At first physical dispatch `review_dispatch.task_acceptance_paid_dispatch_stamp` claims the locked `task_results.task_acceptance_review_accounting` wallet; a claim without a recoverable terminal host run is unknown, not resend authority (§6 Paid stamp and owner custody). A launched review keeps its deadline, task ceiling and per-send money bounds; a deadline cut is DEGRADED, not a free skip.

**Forced rails.** A forced turn sends the round's exact tool envelope so the provider prefix stays a cache hit; "tool-less" describes the instruction and the host, which executes no call, so a reply still requesting a tool is incomplete on every rail and degrades through the host fallback path instead of publishing as the model's final. No forced rail takes another model round, so one shared helper terminalizes a dangling `revision_requested` as `finalized_unaccepted` (`revision_unavailable_on_forced_rail`), naming the prior reason; `accepted` and `finalized_unaccepted` are never overwritten, and the objective stays best_effort. A deadline or a late unread message retains unaccepted work rather than claiming a new subject was reviewed.

#### Headless finalization and workspace patch capture

A workspace task's completion diffs against the captured preflight base, bound to `task_constraint.base_sha` (task-local commits stay in the delta, not `git diff HEAD`); a moved HEAD fails closed only for `self_worktree`, since a shared tree relies on reverse-patch verification, and an unborn repository diffs against the canonical empty tree. `workspace_patch_capture.py` streams the tracked binary diff plus admitted untracked files under the pure rules of `workspace_patch_rules.py`, excluding each vetoed entry with a per-file reason; oversized or binary untracked outputs and tracked files beyond the file-reference size ride a complete manifest+zip artifact instead of a giant patch. Generated output follows the project's `.gitignore` rather than a host directory-name veto, so build deliverables are not silently discarded; git-ignored files sit outside the capture universe, and a sensitive-looking untracked credential is excluded per file as `sensitive_blocked`. `workspace_patch.json` is written for every workspace finalization, no-change and failed included, and `workspace.patch` only for `ready_with_changes`; the CLI strict-patch contract reads them (§1 CLI / Headless Boundary). A forked or empty child drive under `data/state/headless_tasks/<task_id>/data` is execution state: the result copies back to the canonical root, declared artifacts rebase to `data/task_results/artifacts/<task_id>/`, and a late copy-back never overwrites a terminal canonical result. Every child-drive deletion is `task_custody.settle_child_drive`'s decision: the drive goes only when the supervisor's probe proves no live owner for every occupant (unknown keeps it), the durable row is settled and every recorded obligation is held by the canonical row; copy-back never overwrites canonical bytes, and missing or mismatched material keeps the drive until a restore converges.

#### Owner routing verbs

`promote_chat_to_task`, `route_to_project`, `steer_task` and `ensure_project_scope` ride one receipt rail: an act succeeds only once its token-matched supervisor facts are durable in the task result, queue snapshot, annotation or mailbox authority. Among several possible tasks the LLM chooses; code auto-delivers only the unambiguous one-target case, and an unconfirmed or stale receipt fails visibly instead of launching a second root. Receipts are retained per `(owner message, routing token)`; a known rejection returns `rejected` with its reason, never a timeout, so `UNCONFIRMED` means only that no matching receipt exists. A receipt proves admission, not completion.

Who is speaking is one host-minted fact on the event (`control_routing._routing_issuer`; the model has no argument): an owner turn, stamped by the owner door (`is_direct_chat` and `run_origin.owner_ingress`), or a task speaking for itself (a promoted root, a relaying root, or a wake-up, Presence event or template nobody typed). An owner turn's steer travels as owner text: `[Message from my human]`, the owner corpus, the generation bump and the issuing chat's room veto (a Project room reaches its own roots, Main every host-listed root). A task's own words never travel as owner text: the task-message writer shared with `forward_to_worker` sends them as `independent_task` provenance (`forward_to_worker` uses `peer_task` for peers inside the sender's tree) to any host-listed active independent root, rendered `[Message from independent task <id>]`, with no owner corpus (`owner_source_sha256` and the acceptance premises stay the owner's) and no attachments. Neither grants owner authority; author and target ride the receipt, the `task_message_routed` Logs row and the receiver's `task_message_injected` row. Independent roots learn the roster from an `[INDEPENDENT_ROOTS]` tail note (`peer_roster.py`, capped at `ROSTER_NOTE_CAP` rows, cut disclosed). Messaging is model judgment; `forward_to_worker` also reaches inline Presence through its mailbox (§12).

A root may publish bounded `update_focus(text, source_ref)` for other live roots, shown while unsettled and kept on dormant results; publishing is the model's judgment, with no project-level focus, refresh or timer. The `source_ref` answer is retained write-once on the canonical root as `focus.source_handle`; peers read it with `get_task_result(include_focus_source=True, focus_source_sha256=…)` against the physical author's record, so no later focus or retry substitutes its evidence. A refusing reader or a changed snapshot refuses the focus (`FOCUS_SOURCE_UNRESOLVED`). Focus has authored time separate from host observation, no TTL and no owner authority.

`steer_task` relays the owner's exact ingress bytes while the turn still acts on the message that started it; a later drained owner message (`ToolContext.last_owner_delivery`) or a landed routing receipt on the origin ends that window. Past either, the turn relays its own words, keyed on the message relayed and confirmable through the same `routing_wait` poll; mailbox entries are keyed by routing token, so several steers under one origin are several deliveries and a retried emit of one steer stays one.

Every promote/route refusal names its typed reason: the tool result keeps the machine prefix and code, then the host cause words from `project_dialogue.ROUTING_REFUSAL_CAUSES`; `_persist_promote_rejection` is the single durable writer. An empty Project's failed genesis provisioning is `workspace_provisioning_failed`, never a system-repo fallback; the exact Ouroboros repository root as `workspace_root` maps to the disclosed `workspace="none"` sentinel, while a repository subfolder or the data drive is refused, typed. Who is told follows who can narrate: a tool-issued act gets its receipt, error row and `detail`, and the model narrates; a host-issued act (`host_initiated`) gets one typed System row in the owner's chat (`task_not_started`, or `task_start_unconfirmed` for unconfirmed admission) from the one publication boundary `_handle_promote_chat_to_task` wraps around every outcome, never a bubble in Ouroboros's voice; a steering refusal with no owner-message receipt is `steer_not_delivered` (`supervisor/steering.py`). An admitted promote reports its admission receipt's destination, not the requested project (implicit scope re-resolves under the origin claim lock: §6 Project binding by task and by origin), and says so when it lands outside the project the work already has. A promote by a root with an unmet Swarm planning obligation (`owner_hurry.unmet_force_plan_obligation`) carries the obligation onto the new root inside the admission transaction (`supervisor/plan_obligation.py`).

A routing or promote decision turn receives host-built ground truth: each project's registry `working_dir` plus bounded typed projections of the lane's recent root results and live roots, never raw result text. The list is a hint sized by `runtime_limits` and scoped to its receiving lane; the door is the §10 predicate on the result itself, never the caller's room or landing project, and a helper predecessor or a landing outside the predecessor's project is disclosed in the receipt (`_predecessor_notes`) as a free choice. `list_projects`, `route_to_project` and the promote receipt read the project registry through the canonical data root, because a task on a forked execution drive never carries `state/projects.json`. A routing receipt on the same owner message is a fact, never a ban: a second root stays the model's judgment.

#### Explicit starting effort of a root

A root's first round uses `agent_dispatch._initial_effort_for`: the stored `reasoning_effort` when it names an `EFFORT_SCALE` tier, otherwise the configured effort of its role or task type (`OUROBOROS_EFFORT_TASK` for ordinary work: §7). Explicit root inputs are `promote_chat_to_task`/`route_to_project`, `POST /api/tasks` (`TaskCreateRequest.reasoning_effort`), `ouroboros run --reasoning-effort`, schedule templates (owner API, `ouroboros schedule add --reasoning-effort`, `schedule_followup`) and Continue. `settings_scales.requested_effort` validates a supplied tier before any effect; omission keeps the configured default, and a blank or unknown value is a typed refusal on its own surface.

The explicit value rides the queue and the durable admission rows (promotion, API, fired occurrences, Continue, `ensure_control_task_result`); a root interrupted before its first worker write retains it. Continue reads the predecessor root's explicit choice from its result row outside the SHA-bound binding; dispatch stamps children alone, and `switch_model` changes only the live round. The manual-target picker and `/api/decisions` use the same supervisor handlers: a new task admits a root with that tier, an existing-task choice steers without changing its effort. The choice is a request: the first round asks for it, the route may adapt it, and the requested, submitted/clamped and provider-reported facts remain distinct in `request_wire_attempt`. Configured subagent profiles and role-owned efforts (evolution, review, consciousness) are separate axes; effort is not a subagent axis, it derives from the owner's configured effort for the task type (`LEGACY_SUBAGENT_FIELDS`).

### Tool capability and execution

`tool_capabilities.py` is the SSOT for the tool classes and the child allowlists (independent mutation and command ceilings); `tool_policy.py` chooses the initial capability set, `ToolRegistry` is the execution authority, and `loop_tool_execution.py` owns timeouts, concurrency, live evidence, result handling and mutative ceilings. Top-level presets share one built-in name surface: project focus changes the default target, while root policy, runtime mode, task-contract disables, credentials, resources, selected-resource bindings and delegated-child profiles narrow independently, so a registered or discoverable tool is not thereby callable for a particular target. Nothing disappears silently: lazy discovery returns an explicit omission or `CAPABILITY_UNAVAILABLE`, a policy-filtered registered tool is "hidden by policy: <reason>" (`ToolRegistry.policy_hidden_reason`), never "Not found", and a name dispatch cannot run gets one typed answer scoped to the namespace it addresses (`ToolRegistry._name_miss_result`), never a hidden name. `list_available_tools` (`tools/tool_discovery.py`) reads `schemas()` in every mode; `loaded` is residency, not availability. The route's physical ceiling on schemas per request (`provider_models.tool_schema_limit`) is held at the Main round seam (`loop_model_call._fit_route_tool_ceiling`): core, meta and actor-loaded schemas take priority, the overflow tail is left out under a notice naming it and stays callable through `enable_tools`.

Outcome classification keeps policy refusal separate from execution failure, so an expected authority boundary never becomes the task's headline failure: `user_files_path_blocked`, `cwd_blocked` and `artifact_output_undeclared` are typed non-failure surfaces, while a declared output that cannot be registered is the genuine `artifact_output_error`. The identifier register (`tool_result._EXACT_IDENTIFIER_CODES`) applies the same rule to the whole routing and scope refusal family (steer, promote, route, manual target, project-scope bind): a typed refusal is recorded as a refusal, never as `ok`, visible to the agent (`is_error`) without degrading the execution axis — the host refused, the agent did not fail. The delegate tools reach the same register from the producer side (`delegate_shared._fail`): a substrate refusal is `delegate_shared.SUBSTRATE_REFUSAL_CODE` (never degrading), a malformed call `AGENT_FAULT_CODE` (degrades, feeds reflection), never a timeout or generic tool error, and a terminal run in state `failed` or `cancelled` is a successful observation of an unsuccessful leaf. The registry pairs a published typed result with the handler's return only when their texts are identical (`tool_result._publish_tool_result`), so a producer publishes after its last decoration, and a supervising wake is acknowledged on the `supervision_wake_id` that result carries, never on the tool's name.

Tool API v2 exposes only the canonical names from `get_tools()`. The file tools share a path-based public ABI; payload-borne paths (`edit_batch` entries, `apply_patch` targets) miss the dispatch seam that rewrites a `path` argument, so both ends canonicalize through `tool_access.canonical_repo_relative_path` — one normalization keeps a guard from judging `repo/BIBLE.md` while the write lands on `BIBLE.md` — and `_ROOT_ARG_REPO_WRITE_TOOLS` is the single set every repo-write fence keys on. `verify_and_record` (`tools/verify.py`) runs the declared check through the same pre-execution guards as the process tools — a post-execution check cannot gate a receipt already written — and appends a host-attested receipt under `task_results/artifacts/<task_id>/verification_receipts.jsonl`. Process tools report settings changes without auto-reverting, because a revert cannot prove causation (§6 Safety and runtime mode).

#### Resource roots and physical file identity

Filesystem results identify their canonical `root:path`; `run_command`/`run_script` echo the resolved `cwd`. A direct Project room selects one folder for file reads/edits, process cwd, VCS and delegation; governance stays at `system_repo`; a missing folder keeps its address and availability note, never falling back to Ouroboros source, and a folderless task uses its own `task_drive` scratch without workspace or write authority. Resolution preserves physical identity: absolute paths inside a selected base normalize to it, rootless absolute paths bind to their permitted base, outside paths refuse before `safe_relpath` can turn them into similarly named files, and every redirect uses the same resolver as guards and handlers (`ToolContext.repo_path`/`drive_path`); a Docker backend address (`workspace_executor.map_backend_path`) is accepted only inside `active_workspace`.

Roots: `user_files` for user-visible files under the owner's home (the Ouroboros repo and runtime control plane are refused); `task_drive`, task-scoped scratch; `artifact_store`, task-scoped under `data/task_results/artifacts/<task_id>/`, created lazily, where deliverables written through `user_files` or declared process `outputs` are copied for audit (§1 tree); `subagent_projects` and `deliverables`, `read`/`list`/`search` only. The operation matrix (`tool_access_types._POLICY`) is closed under read⇒list,search and write⇒edit, adding no write-like operation to a read-only row. Helpers inherit their parent's physical read reach in every runtime mode, including canonical runtime data and recorded ancestor workspaces, while their write/command ceilings stay independent; a continuation also reads the `task_drive`/`artifact_store` of the one predecessor its contract names (`predecessor_authority.source.task_id`, one hop, read-only). Process admission keeps the original argv and the prepared physical target; command words, script examples and unknown interpreter effects establish no write intent (§6 Safety and runtime mode). The post-execution shell audit (`tools/shell_audit.py`) is observational — no replay, rollback, interpreter or attribution proof — and a failed audit adds a bounded diagnostic (`output_audit_unavailable`) without losing the exit, signal, timeout and runtime facts; computed targets stay a disclosed parser limit, not grounds for a new semantic scanner.

#### Web access mechanisms (three distinct paths — do not conflate)

The three web paths differ in who chooses the query, which model reasons, which authority performs the fetch and where evidence is recorded:

| path | reasoning model | fetch authority | evidence |
|---|---|---|---|
| Main-loop native search (provider server tool, attached only when the main-loop setting allows) | the solve model decides whether to search; no second model enters the scaffold | provider-side | citations and request counts fold into `llm_usage` and the task's host-attested retrieval fact (context for acceptance, never a criterion by itself); the provider-side query is not available to the host |

| Browser tools (`browse_page`, `browser_action`) | the main loop | a local stateful Playwright session that can fetch or act on arbitrary pages | arguments and result previews as tool evidence; browser state is not equivalent to either retrieval path |

For ordinary delegated profiles the URL, route, private-range and control-plane guards apply to local-readonly and acting children alike (`browser_policy.py`, §6 MCP and browser-facing external tools); a Cyber-effective acting child inherits the selected access, explicit task restrictions remaining. Ordinary delegated access to non-loopback private origins requires host-established `resource_policy.allowed_origins`: Main/root scheduling names it in `schedule_subagent`, delegated and external Presence callers can only inherit or narrow it (`tools/control_subagent_spec.py`), and the origin normalizer rejects paths, credentials and wildcards; among delegated profiles, only a valid acting child may run JavaScript `evaluate`, on its current page. #### Context fitting, retry, and compaction

`config.get_context_mode()` is the effective Main sizing source and `config.get_owner_context_mode()` the persistent owner-intent/P3 source; they differ only during the auto-Low compatibility window (`context_mode_compat.py`). `prompts/SYSTEM.md` and `BIBLE.md` are tier-0 and full in every projection (`context_layout.TIER0_ALWAYS_FULL`). `llm_local.py` sizes the local lane by confirmed `serving_context_evidence` (the owned server's live `--n_ctx`); `get_context_length` is metadata, not capacity, and an unknown window skips compaction and implies neither failed health nor cloud fallback. It can still cut BIBLE's `## Principle` bodies, a live defect (issue #1018).

`context_fit.py` renders the Max, Low and Nano views of one immutable conversation core and measures every Main candidate on one labelled density basis (`estimate_context_prompt_tokens`) against the route's capacity; the targets live in `context_budget.py` (`OWNER_LOW_TARGET_TOKENS`, `OWNER_NANO_TARGET_TOKENS`), and crossing one is never a failure. Budget reservation counts raw characters, because over-counting money is the safe side. Capacity or economy-target pressure requests one reclaim pass over mutable history (checkpoint `context_reclaim`), sized to land below the boundary by a low-water margin (`RECLAIM_LOW_WATER_DIVISOR`) to avoid re-arming on the next round's growth. Only a real provider overflow moves a Max task to task-local Low; a known window too small for even the shortest memory view with books, tools and reply reserve puts it in Low or Nano (`memory_floor.physical_mode`, checkpoint `context_fit_physical_mode`; a route switch re-renders from the captured core, `ContextFitPlan.reproject_for_route`); owner mode and P3 applicability never change. The transport finalizer `llm_attempt.bound_reply_allowance` applies `context_budget.reply_allowance_tokens`: Low and Max keep the caller's ceiling; Nano adapts to the known window or its economy target, with `NANO_MIN_HEADROOM_TOKENS` bounded by that ceiling as its floor. Unknown capacity stays unknown. `context_health.build_health_invariants` runs once per task attempt, so the Health Invariants block is a task-start snapshot whose delegated-run lines are ownership-aware (§6 Delegated subagents); its engine-exit line reads only the recent supervisor log and names the observation time, not a death time, and whether to tell the owner is the agent's judgment.

`send_clock` stamps each new physical Main candidate before measurement, pricing and sealing, so compatibility retries prove clock-free equality and same-invocation rejoins keep identical bytes. `context_compaction.py` is a requested materializer, not a second threshold, timer or retry authority: the fit decides when and how much; automatic summaries use only units a usable attempt actually exposed (`exposed_context_units`; unknown exposure keeps a unit raw), writes an exact private checkpoint before any summary, keeps owner turns verbatim and every original restorable, and with no eligible positive reclaim makes no checkpoint, no summarizer call and no transcript mutation (one route+round latch per automatic pass). `compact_context` (`record_context_view`) gives the actor the same materializer for a working view, published at the successful-response boundary before returned tools execute; no helper model rewrites the authored note, `owner_wait.continuation_state` keeps the exposure observation across a resume, and estimates at the tool boundary are disclosed, not admission gates.

Ouroboros stores one provider-neutral, function-shaped conversation; each route projects a physical copy. OpenRouter's copy omits the neutral `tool_choice="auto"` and sets `strict: false` on function tools lacking it, because the Responses API serving OpenAI models there otherwise attempts strict mode and requires every property. Direct OpenAI tool traffic stays on Chat Completions; `openai_chat_custom.py` maps only the physical copy to Chat custom tools and back, and its custom/function/none ladder advances only on an exact dialect rejection, never learns the fallback durably and never moves the conversation to another API surface, model or provider. Direct Anthropic tool turns keep a private route-bound receipt of the full native assistant `content`, replayed on the next same-route continuation and scrubbed on any provider, endpoint, API-surface or model change. `request_wire_recovery.py` repairs a rejected request's shape on the same credential-free route and profile (`set_value`, `drop_field`, registered `replace_dialect`; `_MAX_COMPOSED_ACTIONS` per call inside the existing send, pricing, Stop and deadline limits) and never chooses a provider, model or API surface; only a valid normalized success bound to the exact settled physical capture teaches `state/request_wire_compatibility.json`, so prose in an error body cannot reroute. `usage.request_wire` discloses the wire attempt; `state/usage_attempts.jsonl` owns money.

Retry budgets are failure-class specific: empty or incomplete responses and transient 429/5xx failures may retry the same model with deadline-bounded backoff; auth, quota, permanent bad requests, confirmed oversize and output exhaustion (below) fail fast; exhausted compatibility returns to the configured model fallback chain rather than becoming a second router. `LLMClient` keeps leading system messages authoritative and demotes later ones to visibly marked user notices. Physical custody classifies failures: a remote pre-dispatch failure is `transport_unavailable` (`loop_llm_call.classify_llm_exception`: released, $0), one physical attempt per call. One provider's failure does not prove dead egress — `loop_model_call._recover_failed_round` tries configured alternatives, remote included, before the `loop_transport.py` episode waits (interruptible backoff, durable `network_wait` rows, progress that keeps the idle rail alive) and redials the same round under the bounds in the table. A dispatched response stays eligible, because the wait bound never cancels in-flight cognition; expiry takes the no-resend terminal. Closing rows prove cooperative exits only: external kill, Panic, crash or hard Stop require a confirmed terminal result, never inference from silence.

`provider_outcome_unknown` keeps the dispatched attempt's unresolved monetary bound; the same request is not resent. `loop_transport.new_generation_after_unknown` admits a new, possibly charged request only after receiving has ended without a usable answer and no same-operation rejoin is viable (`same_operation_recoverable` reuses the operation or idempotency key); `append_unknown_recovery_input` binds the new attempt to the old id, route and unknown cost, and only the current accepted message executes tools. One live delegated leaf makes its supervising task enter `delegate_hold.py` instead, where only a meaningful leaf wake supplies new-round input. Inline Presence alone opts its primary round into the transport-death repeat (`_dispatch_round_model`, `transport_death_retries`): a typed transport death (`transport_custody.is_retryable_transport_death`; never a timeout, provider error, pre-dispatch failure, local or loopback route) may be repeated as separate ledger attempts, each an unresolved upper bound, until `llm_non_retryable_same_request` marks exhaustion or a pending `finalize_now` or deadline refuses the repeat. Otherwise Presence takes the no-resend terminal (§12); forced-final, review, safety, probe, search, consolidation, reflection and external Agent runs keep their own no-resend contracts.

Retry rails nest, each with its own owner and bound; the table makes the multiplication visible in one place (a physical send is always its own `execute_physical_attempt` lifecycle, whichever rail asked for it):

| Rail | Owner | Bound | What it repeats |

The OpenAI-compatible, no-proxy and web-search clients share one transport factory (`net_transport.py`) that sets platform-guarded TCP keepalive socket options (thresholds from `config.py`), so a NAT or VPN mapping silently dropped during a long silent reasoning stretch is detected by kernel probes instead of hanging until the read timeout; proxy-routed installs, the Anthropic-native `requests` lane and platforms other than Linux and Darwin run without the tuning. Trust anchors ride the same seam: `net_transport.extra_ca_bundle` merges the owner's `OUROBOROS_EXTRA_CA_BUNDLE` PEM over certifi into a content-addressed `state/extra-ca-bundle/<digest>.pem` that every first-party client verifies against, so a corporate or national CA is an owner setting rather than a system-store edit; an unreadable file is a loud `ExtraCaBundleError`, never a silent fall-back. Main-loop model cognition is a typed in-flight fact: the worker sends the supervisor a `started` event bound to the exact attempt, execution, round, call and retry before each provider call and the matching terminal after it, so a stale terminal cannot clear the current row, and the supervisor consults that process-local row only in the idle predicate, without elapsed-time expiry. `OUROBOROS_LLM_TRANSPORT_READ_TIMEOUT_SEC` is a dead-socket bound, not a cognition deadline; deadline, budget, cancellation and the absolute ceiling stay independent hard axes.

OpenAI-compatible choices keep their outer `finish_reason` as the usage fact `response_finish_reason`, never in canonical history; Main's finish consumers and the consolidator share one reader (`_usage_response.response_finish_reason`) and one output-limit vocabulary (`length`, `max_tokens`). An empty reply without a body error that ended on that limit is output exhaustion (`llm_empty_response`, kind `llm_output_exhausted`): no cooldown, cache bypass or `infra_failed`, no provider terminal, no route walk — one host fact (the sent allowance and reasoning tokens, when recorded) opens the next ordinary round, which decides how to continue within the existing limits. Overflow and body errors keep precedence; a missing or null finish stays a glitch.

#### Prompt caching

Prompt caching is stable-first: governance and task-stable contracts precede mutable evidence, review builders disclose the stable/dynamic boundary, untrusted payloads stay outside the governance cache block, and `context_fit.seal_task_transcript` owns the single message-side breakpoint. OpenAI-family caches look a prefix up only at message ends, inside the leading system group only at its end, and a changed tool set is another prefix, so that group plus the tools is one cache unit; changing runtime evidence therefore stays outside it, where it cannot invalidate the stable prefix reused across conversations. The Main builder therefore declares its stable prefix — `context_fit.ContextFitProjection.system_message` stamps `STABLE_PREFIX_BLOCKS_KEY` over every nonempty block before C (host-only, popped from every send copy) — and the OpenAI-family send copy (`llm_attempt.openai_family_route`) and the Claudexor send copy for every model source (`llm_claudexor._request`) keep A' (prompt, Bible, Architecture, a common book pointer), optional D (Development) and B (identity and the sealed story) as separate system items and carry C (knowledge, rooms, runtime facts) as one `[SYSTEM NOTICE]` user message with a byte-stable provenance header right before the task (`llm_messages.split_leading_system_prefix`, placements in `SYSTEM_PREFIX_SPLIT_PLACEMENTS`); on OpenRouter this family keeps message markers (`llm_attempt.supports_message_cache_control`), other families keep byte-identical wire. OpenRouter's sticky session follows the same family line (`llm_routing._openrouter_session_identity`): the OpenAI family shares one session per model + governance prefix, so a new task, child or wake is served the prefix its predecessors cached. The shape sent is recorded per call (`usage["wire_layout"]`). The Health Invariants cache-hit rate counts only rounds that report `cached_tokens`, so a provider without that telemetry is unmeasured, not a miss. Residuals: the shared family session pins a model's traffic to one OpenRouter endpoint while it lives; a cached prefix expires after idle time, so a quiet install gains nothing; a mid-task tool-set change still breaks the unit. Gateway response-cache recovery is reactive and narrow: only a main-loop `provider_incomplete_response` arms a fresh-response request, and only the generic `openai-compatible` route renders LiteLLM's `extra_body.cache.no-cache` control.

#### Background consciousness and Evolution

Background Consciousness takes an ordinary Main direct turn (`_is_direct_chat`) when nobody wrote: the same system prompt, context builder, tools, chat/activity and usage ledger, with `prompts/CONSCIOUSNESS.md` (rendered by `consciousness_wake.py`) as its user message. `consciousness.py` owns the clock and schedules the next wake from the last finish and selected interval; owner messages do not trigger wakes. `toggle_consciousness(status)` answers from a write-free `state/state.json` read and reports unknown rather than guessing; start and stop stay supervisor acts announced to the owner. An official-update check (Runtime context's `official_update`, `update_letter.py`) forces no wake; the model decides whether to mention it.

A wake sees the Main turn's own view (`memory_view.ROLE_DEFAULTS["consciousness"]`: the integrator's spec with Main as its room, since a wake has no chat of its own) — my story, all marks, `## This room (Main)` byte for byte as the Main turn renders it on the same snapshot — plus, in `## Live rooms`, the words of people in every other room whose open conversation is not yet sealed into a page, the memory still held only in a helper's retelling, and the journal records written since the last accepted wake. They are facts, not a duty: the wake seals what it judges ready with `chronicle_write`. The wake text gives the cause, settled facts, those memory records (one line, author and an exact read each) and every answerable owner card. `consciousness_observation_boundary` holds a committed chat cursor, the last observed memory-journal sequence and a digest-bound reference to the immutable wake source, and advances only after readback verifies the source, so a fact written during a wake reaches the next one. The alarm finish `consciousness_last_wake_at` is a separate fact; until a verified boundary exists, `consciousness_observation_bootstrap_since` keeps the initial lower bound, so events received during the first wake cannot be skipped.

Three metadata facts distinguish a wake-up from an owner's turn. Origin is `metadata.initiator == "consciousness"`, inherited by everything the wake starts; no owner door stamped it, so it speaks to tasks as a task, never as the owner (§6 Owner routing verbs). Authority is the owner's autonomy level (`metadata.consciousness_autonomy`, owned by `consciousness_authority.py`): Observe researches, keeps internal notes, stops children it started, governs existing schedules through a narrow surface and may delegate read-only research; Act (the default) withholds, by exception list (`ACT_DISABLED`), evolution, restart, the one settings writer, its own alarm and Presence configuration, and the `light` mode cap keeps it out of Ouroboros's own code; Full has neither. A level's structural consequences are an exception list in `task_contract.disabled_tools`, a per-task `runtime_mode_cap` of `light` below Full, and Observe's argument-level narrowing: `OBSERVE_ARGUMENT_NARROWED` lists the mutating-table names Observe still sees because each has a read-only or own-work use that withholding the name would destroy with the mutation, and one predicate, `observe_argument_refusal`, consulted directly by the dispatch guard, decides what such a name may be asked to do — no fail-open wrapper, since a policy that cannot be consulted must not read as permission. `cancel_task` alone narrows by durable lineage through the tool's own-child custody check (`join_ledger._cancel_task`), so Observe may stop children it started, never the owner's running work; a read-only child may delegate read-only descendants under the inherited depth cap but never passes a mutating delegation budget onward (`delegation_may_mutate`); `manage_schedules` (`tools/followup.py`) lets the root turn list and change, a delegated task only list, a Presence conversation neither. For a consciousness-origin task the list binds at dispatch only: tool schemas and the cached prompt prefix stay byte-identical to an owner turn's, a withheld call gets the typed dispatch refusal when made, and the wake message names the level. The stricter of install mode and cap binds at every mutation gate, the acting-child write surface, subagent patch integration and a started task's Runtime block, so the owner's level holds on any install. Money is one rolling 24-hour allowance over wake-ups and every root tree they start, read off the usage ledger (`consciousness_allowance.py`) by the alarm before waking and by the one admission door (`supervisor/queue.py::enqueue_task`) before requested work starts — no "consciousness task" type, only existing tools through the existing door; a Presence cycle a wake starts is an independent root outside it. The allowance decides on known spend, holds disclosed beside it. The remainder, capped by the owner's per-task cap, is the wake tree's producer ceiling (`root_cost_ceiling_usd`): the in-task stop fires when known spend reaches it, with no planning margin, and exact-continuation eligibility decides between a saved pause and a terminal result; the ledger fence keeps the per-task cap, so only a zero daily remainder blocks a wake.

An active evolution campaign owns its objective, id and transaction/task claim (`supervisor/evolution_lifecycle.py`); `evolution_mode_enabled` only projects scheduling. Dispatch, review, commit, publication and restart revalidate the claim; restored work without a live uncommitted claim is cancelled; publication binds the exact reviewed SHA, and `state/pending_restart_verify.json` binds restart verification to the claim even when auto-restart is off. Cleanup restores a no-op or abandoned admitted cycle's base while preserving dirty or ahead work in recorded stash/refs; a review-verdict block on an identical diff replays free, a changed diff permits review under the shared cycle cap; append-only `evolution_checkpoints.py` records Git/memory identity, cost, rounds and omissions for learning. An agent-requested restart drains heartbeat-fresh tasks within its bound, then refuses rather than cutting live work.

Post-task evolution is owner-gated and default-off (`post_task_evolution.py`): the worker may recommend one backlog item by writing a durable request — never enqueuing or enabling evolution itself, and never from an evolution, deep-self-review or subagent task — and only the supervisor's idle tick converts it into one normal campaign cycle; a temporary review block does not permanently prohibit reconsideration. An owner stop closes the campaign, clears queued requests, persists `evolution_owner_stopped` and cannot be autonomously reversed. Evolution is hard-blocked in `light` runtime mode at the owner and post-task start entry points, again at idle campaign enqueue (`supervisor/evolution_lifecycle.py`) and again at assignment (`supervisor/worker_assignment.py`); it uses the normal task/review path in `advanced` or `pro`.

Loop self-checkpoints are plain user-message reminders, because a structured, tool-less reflection protocol in the hot loop produces unusable records and breaks cache continuity. The reminder's recent-call list carries each call's recorded outcome and, for a failed call, the first line of what the tool answered: host facts only, no threshold, no repetition verdict, no stop. It is built from `llm_trace.tool_calls`, so name, arguments and outcome come from one record; joining the visible transcript to the trace by call id cannot be made sound, because providers reuse ids while compaction removes whole units, so without a trace the calls render with no outcome rather than a borrowed one. Durable learning belongs to the post-task reflection flow (§6 Post-task reflection).

### Safety and runtime mode

Tool dispatch uses the registered capability, the explicit task/resource contract and one prepared physical target. Explicit task resources and the actual Git target are host facts, distinct from any semantic judgment about the call; this is not an OS sandbox.

Runtime mode is effective Access and a self-modification ladder. Light refuses mutation of the Ouroboros repository and control plane (`LIGHT_MODE_BLOCKED`; skill payloads under their own root stay editable) while user deliverables outside them remain buildable, and Light cognitive writes go through `update_identity`, `update_scratchpad` or `knowledge_write`. Advanced evolves the application layer but not the protected set owned by `runtime_mode_policy.py` (`SAFETY_CRITICAL_PATHS`, frozen contracts, release/managed invariants — one policy shared by the registry, git tools and gateway guards, refusing typed `CORE_PROTECTION_BLOCKED`). Pro may write that set, announced by `CORE_PATCH_NOTICE`, and its commit still passes the normal review wave (both questions). Cyber authority derives from effective Access (`runtime_mode_policy.mode_has_unrestricted_agency`); a saved next-boot mode never rewrites a running task. In Cyber Pro, internal review and Safety findings are advice under BIBLE P0/P3: configured enforcement, independent assessments and the decision to proceed remain distinct facts.

Process admission preserves the original argv and the resolved cwd. Command words, quoted source examples and unknown interpreter effects are not proof of a forbidden action: `shell_parse.py` and `tools/write_shape.py` supply observed targets and syntax facts, never permission judgments. The Safety Supervisor (`safety.py`) judges each call on the light-model route from the complete retained owner directives, the task contract and constraint and the prepared resource target; a bounded recent-conversation view supplements that source, never replaces it. Coverage is `OUROBOROS_SAFETY_MODE` Full/Light/Off over each tool's `TOOL_POLICY` entry (`skip`, `check`, `check_conditional`; an unknown tool is checked): Light skips conditional checks, Off skips every Supervisor call, and every waved-through check leaves a durable `safety_mode_skip` event. `full → light → off` is a decreasing coverage ladder, so outside Cyber Pro a downward step is owner-only (`POST /api/owner/safety-mode`). Each admitted process effect executes once; later settings or repository observations annotate the original result and never repeat or roll it back. Settings-selected environment (`env_from_settings`) reaches commands, scripts and verification under the same Settings-selection authority as service startup; `tools/process_facts.py` resolves it once after admission and masks diagnostics before persistence.

#### Safety Supervisor outcomes

The first line of a Supervisor result is the typed outcome. SAFE passes silently; SUSPICIOUS allows the call with `SAFETY_WARNING`; DANGEROUS or an answer still unusable after one repair retry blocks with `SAFETY_VIOLATION`. Cyber records a negative or unavailable assessment as advice (`SAFETY_ADVICE`, durable `safety_advisory` event) without manufacturing SAFE. A provider 429 is an infrastructure fact about the Supervisor, not a verdict about the call: after one retry the call is blocked with the typed non-verdict `SAFETY_UNAVAILABLE`, which tells the agent to retry the same call rather than reword it, and a confirmed storm arms a process-local latch (`_SAFETY_STORM_COOLDOWN_SEC`) that answers in-window checks without a provider call, because re-probing from the highest-frequency light-model consumer would amplify the storm it reports. A structured insufficient-quota refusal is a verdict and blocks. A subject over `_SAFETY_SUBJECT_CHAR_BUDGET` is refused fail-closed (`SAFETY_SUBJECT_TOO_LARGE_BLOCKED`), never truncated, because anything past a cut would run unreviewed. The no-backend cases alone fail open with `SAFETY_WARNING`, so a misconfigured runtime does not hard-block every unknown tool: (a) no provider key and no local lane; (b) a remote key that does not cover the light model's provider, with no local lane; (c) a local runtime chosen as fallback that fails or is rate-limited. An explicitly primary local runtime (`USE_LOCAL_LIGHT`) that fails is a real `SAFETY_VIOLATION`.

Outside Cyber Pro, read-only shell git is allowed everywhere; mutating shell git only when its resolved target lies outside the Ouroboros system repository and runtime data drives (`git_shell_policy.py`; `git init`/`git clone` are judged by destination). Acting `self_worktree` children remain read-only because patch capture requires an unmoved HEAD. The generic VCS tools (`vcs_status`, `vcs_diff`, `vcs_pull_ff`, `vcs_restore`, `vcs_revert`) default to `root=active_workspace` and accept explicit `root=system_repo`; protected Ouroboros path names constrain restore/revert only on that system target, so a project's own `BIBLE.md` or `contracts/` is ordinary project content, while `preflight_review`, `commit_reviewed`/`vcs_commit_reviewed`, `vcs_rollback` and promotion remain system-repository lifecycles. First-party PR helpers are ordinary built-ins under the same root policy, runtime mode, delegated-child constraints, credential rules and reviewed-publication authority. Outside Cyber Pro, a task contract may declare `resource_policy.protected_artifacts[]` as execute-only black boxes (`protected_artifacts.py`): execution is allowed; reads, copies, hashes, static inspection and trace/debug wrappers over those paths are refused.

### Review delivery

`review_execution.py` routes are `api_chat` and `agent_session`; vendor and harness names are targets behind the transport, not route kinds. #### Native tool-round episode

`review_native_episode.py` (`NativeToolRoundReviewExecutor`) delivers every retrieving API row: every review-pool seat whose catalog row carries `delivery: native` (commit gate, `review_change`, preflight, plan, skill and acceptance surfaces; `reviewer_slot_config.review_pool_slots` sets `ReviewSlot.native_retrieval_override` from that row) and the deep self-review row, which binds the episode directly. The two-part brief belongs to the commit gate, `review_change` and the preflight; plan, skill and acceptance seats carry their own questions and output contracts. One episode is one logical review attempt: `chat(tools=…)` rounds against a fresh instance-local read-only inspection registry (`read_file`, `list_files`, `search_code`, `query_code`, `vcs_status`, `vcs_diff`, `compact_context`; the `local_readonly_subagent` constraint, network off) until the reviewer answers. There is no round cap (P13); four bounds hold instead: the send bound `review_native_transcript_bound` — min(owner ceiling `OUROBOROS_REVIEW_NATIVE_MAX_TRANSCRIPT_CHARS`, the reviewer window's calibrated capacity in chars), checked before every provider call — the owner `deadline_at` and slot window clamping each transport timeout, the loop's per-tool timeout on inspection calls, and the paid ledger pricing every physical send as its own attempt. Mandatory reading never raises the send bound: a surface's `policy["native_mandatory_read_chars"]` is read through successive working views (`compact_context` authors a new view) and a shortfall is disclosed as `native_mandatory_read_disclosure` = `native_multiple_windows_required`, not refused. Host-observed coverage of `policy["native_required_sources"]` folds into `native_read_coverage`, diagnostic evidence beside the verdict, never an episode stop, a lost quorum seat, a commit block or a paid repeat (§6 The coupling question (Part 2 of the brief)).

A bound with no room for the first send (`native_bound_below_first_send`) or a registry without projectable inspection schemas (`native_inspection_unavailable`) is a pre-send refusal, `not_dispatched` ($0), so the execution wire never mints a native run that never sent. The host posts one `[EPISODE_BUDGET]` landing notice per working view at `NATIVE_LANDING_FRACTION` of the bound; exhaustion is a typed refusal (`native_transcript_cap_exceeded`) for verdict shapes and a disclosed `native_incomplete` product for the report shape. An episode that ran paid rounds is dispatched in custody whatever exception ended it; every end leaves one `review_native_episode` custody row and its facts on the actor usage. Read evidence rides that usage as host-observed `native_tool_receipts` (`host_file_read_attestation: host_observed`) stamped by the reader itself (`ctx.last_read_view` in `tools/core_file_tools.py`), so a bounded read is distinguished from full coverage without trusting the model's path spelling, and a missing stamp proves no extent. The output contract follows the surface's shape (`triad_review.default_output_contract`) unless the surface supplies `policy["output_contract"]`.

#### Late completion and typed refusals

Late review completion is retained in the operation-addressed prompt/response CAS (`review_substrate.py`, `review_custody.py`): the response manifest stamps the complete producer outcome with its full task/attempt/slot/operation/subject/contract/roster binding, so exact reconciliation verifies that source and runs the existing surface reducer without a second paid attempt; pending, unreadable, mismatched and unknown outcomes keep custody. Plan and Skill Review waves travel the same path (`review_job.review_wave` reserves slot operation ids before paid dispatch; a `review_resume_of` continuation reaggregates only the immediately preceding unsuperseded wave with identical material and contract). Late completion alone never revives a job or enables a skill.

A delegated review seat's custody is the run's, not the worker's. A rejoin after process loss (`review_custody._rejoin_window`) runs for what remains of the run's original window, from saved facts only, floored at `NESTED_SETTLEMENT_MARGIN_SEC`: a repeated collect never extends it. A transient failure to observe a live run is not the run's failure: polling continues until a terminal or the slot deadline, and when the deadline read is unreachable too the seat stays `in_flight` (typed `ReviewPollUnavailable`) for a later attach-only observation — never settled, never retried. A `succeeded` first seen by the deadline read is paid evidence and is accepted (`late_success_accepted`); `cancelled`/`failed` terminals are never late-accepted. Terminal delivery derives a bounded host notice from the delegated-custody audit beside unchanged model text, so a later cancellation never rewrites historical authorship or the answer hash.

A malformed catalog is refused at save (`reviewer_slot_config.review_pool_save_error`) and is a typed loud failure on every review surface (`reviewer_slot_config_invalid`); an empty pool is the distinct typed fact `pool_empty`, on which the commit gate dispatches nothing and records review not performed. The preflight and `/review` read no slot: each call names one enabled catalog row, and an unknown or disabled row is a typed refusal, never a fallback. No surface silently chooses the opposite route or a default panel. Technical failure and commit permission are separate facts: producers keep the failure origin beside the original status and findings, and what each enforcement mode permits after such a failure is the protocol's rule (DEVELOPMENT "Review & Commit Protocol"); neither changes quorum.

### Usage ledger substrate vs. accounting policy

`usage_store.py` owns the monetary authority, `state/usage.sqlite` (one row per physical attempt, updated on every transition; [Usage store](../USAGE_STORE.md)); `usage_ledger.py` is the shared vocabulary leaf (typed errors, row and transition rules, drive root, name lock) that policy modules import and that imports none of them. `usage_accounting.py` is the one-way policy layer above them (pricing, reservations, settlement, scopes, budget fences, projections, admission). The boundary means a pricing or budget-policy change cannot redefine valid storage, and a locking or repair change cannot change what an attempt costs; events, state mirrors, task fields and UI projections may carry attempt ids and derived totals but never become a second charge source. `_usage_response.py` is the one normalizer of a provider's usage block for accounting: a zero-usage body error settles at a confirmed $0 and releases the reservation, so a provider storm cannot manufacture phantom budget exhaustion. Every provider adapter still reads the raw `usage` dict for its own envelope; there is no central read to consolidate.

`claudexor::<source>=<model>` selects a model operation in the Ouroboros-owned engine, not an Agent Run: `LLMClient` dispatches sync and async calls through `llm_claudexor.py` before the OpenAI-compatible filtering and retries, and Ouroboros keeps its SYSTEM, BIBLE, canonical messages, tool selection and execution. `ClaudexorGateway` (`gateways/claudexor.py`) drives one idempotent operation per model call (`POST /v2/model-operations`), and the engine performs at most one generation per operation: a lost local HTTP reply rejoins the same operation, an unknown provider outcome never makes the engine generate again, and a host generation after an eligible unknown is a new operation. It shares its managed profile with Agent sessions (the official CLI keeps refresh ownership) and uses no relay process, copied operator auth store or public OpenAI-compatible endpoint. Metadata helpers use `read_owned_gateway` (owned-only discovery; never installs or starts the engine); model calls and explicit lifecycle actions use `ensure_owned_gateway`. Only the exact `model_request_invalid` create refusal proves validation failed before command admission; a generic HTTP error or failed status read cannot prove non-dispatch. Error events carry the provider's sanitized typed `vendorCode`/`parameter`; unknown outcomes expose no provider details.

Physical attempts stay in the usage store, where exact zero cash, known charges, estimates and unknown cash remain distinct — a subscription is not evidence of zero cost. Compact operation receipts survive the engine's body deletion, so an expired read cannot start a new generation. Private continuation envelopes stay in canonical history but out of public/summarizer projections. Image capability on these routes comes from the selected account's model catalog (§6 Vision and local image evidence); missing metadata is unknown and image input is kept for the real call. The send copy omits foreign envelope metadata such as `stop_reason` and keeps a nonempty `refusal` as assistant text, so moving the cache boundary never rewrites bytes already sent; the transcript is append-only between sends (§6 Task lifecycle). `effort_evidence.py` validates the engine's effort reports without remapping native tiers; missing or malformed is unknown, and Logs separate reports from host-requested options.

#### The live turn slot

Beside assistant-level history the engine keeps one live turn per model client session, and its opaque token is transport, not content: it belongs to the caller that is running, not to any stored message. The caller owns a single mutable slot (`llm_claudexor.ModelTurnState`) that rides the ordinary `LLMClient.chat` parameters to the engine boundary, the only writer: a dispatched durable result replaces it, a released `invalid_continuation` repair clears it, other outcomes preserve it. A slot rather than the transcript, because the live turn survives compaction that drops the messages and outlives a body that fails after its headers, so the last stored assistant envelope would rebuild the wrong lifetime. One `run_llm_loop` invocation is one turn, continued across rounds, owner steering, acceptance follow-up and quota waits; a next loop and a cold restart start empty; a consciousness wake-up is one such turn keyed by its task id; a dispatch that leaves this transport ends the turn for good. Opting in requires an engine at `config.CLAUDEXOR_MODEL_TURN_STATE_MIN_VERSION` as read from the last successful handshake; an older or not-yet-observed engine keeps the request shape without the slot. Holding state never licenses another generation; the token is never usage, an event, a progress note or a task card. Mechanism: the `llm_claudexor.py` docstring.

Main remote completions stream (`llm_stream.py`), assembled inside the physical send closure before accounting settles: a complete stream yields the same normalized response shape as JSON; a partial stream never yields a usable tool call or answer, and its exact wire bytes and partial assembly stay in private CAS through the `physical_stream` manifest and attempt id. Ordinary control-link, create, status and result-read failures, generic 404 included, rejoin the same operation or create key across endpoint rediscovery; they do not prove non-dispatch and cannot start another generation while the existing operation remains recoverable.

#### Delegated spend and token reads

**What a delegated run costs.** Claudexor reports cash per attempt (`attemptExecution[].usageCost.cashUsd` with `cashKnowledge` exact|estimated) and in `summary.spendUsd`/`summary.spendEstimated`; `delegate_custody.disclosed_spend` is the single reader, preferring the per-attempt figures, so the ledger row and the payload the nanny relays cannot tell different stories. Runs ask `authPreference: subscription` explicitly, because the engine default falls back to a paid key invisibly. Four cases:

| disclosure | ledger | finality |
|---|---|---|
| disclosed settled zero | `0.0` (`subscription_session` row) | `cost_final=true` — the proven free session |
| disclosed settled charge | the amount | final |
| estimated amount | the amount | `cost_final=false` — an estimated zero is not a proven free session |
| undisclosed | `cost_usd: null`, increments `unknown_unmetered` | drops `cost_final` for the projection |

An undisclosed spend contributes `0.0` to known `settled_usd` and `accounted_usd` — inventing a conservative bound would fabricate a number the harness never gave (BIBLE P1) — so a `TOTAL_BUDGET` fence cannot stop spend it was never told about; the honest consequence is loss of finality, not a guessed charge.

**What a delegated run reads.** Harnesses count input tokens with incompatible conventions, so `settle_run` copies the engine's normalized `summary.inputTokenUsage` onto the `subscription_session` row as the optional `input_token_usage` object; `record_subscription_session` is the one validator, and a partial object is unknown as a whole, because a repaired counter reads exactly like a measured one. The object stays outside the idempotent row identity, so an engine that starts reporting never rewrites a session already settled without it.

#### Nanny, transport and custody

**The nanny model.** An `agent_session` child is an ordinary recursive nanny task supervising at most one active bounded external leaf. Task lineage, authority, deadline, money, acceptance, cancellation and descendants stay with the task; the harness is a nonrecursive tool leaf, and host-authored verification checks its claims. `requested_depth` is absolute root-depth telemetry, `depth_remaining` the narrowing cap. Targets and access profiles are opaque to core: no harness-name capability or fallback branch; login asymmetries stay in `gateway/claudexor_accounts.py`.

**Transport.** `gateways/claudexor.py` owns the descriptor, the /v2 handshake and the `config.CLAUDEXOR_MIN_VERSION` floor; the client runs with `trust_env=False` so a shell proxy cannot intercept the bearer token, which grants all of /v2. Stop, latch and failure: §9.

**Durable custody.** Runs may outlive workers. The canonical and budget-root `delegate_run_*` rows (`delegate_custody.py`) are the authority, read through the `delegate_custody_memo.py` process memo, which refolds on any doubt and bypasses itself when the chain is unreadable. Ownership is OWNED/FOREIGN/UNKNOWN: absent custody is clean, unreadable custody is `delegated_run_state_unknown:custody_log_unreadable`. `logs/containment_faults.jsonl` keeps unresolved incidents beyond event-log tails.

Before `delegate_run_start_requested` a private CAS retains the full unredacted envelope; a missing or corrupt body keeps the pending identity unknown, without a POST (`delegate_pending.py`).

`reconcile_orphaned_runs` settles terminal runs outside the live owner set; cancelling a live run requires a readable, truly terminal owner-authored finish. A `RunCustody.review_owned` run belongs to its panel, kept `left_live` unless the owner cancels and never reposted by generic recovery. Provider or transport death, a worker crash or an unreadable result spare runs as `left_live`: `maxSeconds` bounds damage, not custody. After ledger persistence, SETTLED is published before registration retirement: a failed retirement replays, a failed ledger write cannot settle. Registration lifetime follows continuation authority (`delegate_registration_policy`): review registrations retire at once, while `delegate_continuation.still_continuable` retains any project whose line can still continue (a live owner, a validated retry or Continue successor, an eligible Continue offer) or whose authority is missing or unreadable. An unrecorded start stays `started_uncustodied` until positive absent/terminal proof.

**No terminal/cancel claim without a verified receipt.** `delegate_cancel` returns `confirmed` (terminal readback), `requested`, `failed` or `containment_fault_run_may_still_be_live`; the last two keep a durable critical incident until a receipt or settlement, and a refused control never proves run state. `daemon_says_absent` accepts only an answering daemon's scoped 404, never a failed observation; `delegate_run_closed_absent` means unreachable, not settled, with no invented terminal, usage or spend.

#### Nanny verbs and continuation

**Five nanny verbs** (`tools/delegate.py`): `delegate_start`, `delegate_wait`, `delegate_cancel`, `delegate_answer`, `delegate_message`; no fake hurry. Start needs an exact session `subagent_id` or recovery-only `retry_of`; `subagent_bootstrap` starts the snapshotted leaf before the first model round, and the model decides when to wait. `delegate_message` (`delegate_interactions.py`) requires the engine’s `/v2/operations` catalog to advertise `POST /v2/runs/:id/messages` and a route `liveInput` other than `none`; the gate uses no harness-name branch. Outcomes mirror the engine's `LiveMessageOutcome`, where `delivered` proves consumption, not obedience, and steering is attempt-local, never re-injected by the host. An unreadable capability is `capability_read_failed`, not proof that live input is unsupported. A `not_active` refusal with `interaction_pending` may carry a fresh question observation and exact pending-interaction ids through the ordinary complete/preview artifact path; the refusal is preserved, unreadable observations stay unknown, and nothing is auto-answered.

A definite refusal needs a typed cause, no custody handle and either producer `definitely_unrun` or `_DEFINITE_UNRUN_REASONS`; it ends UNRUN at $0. Ambiguity wakes the model: uncertain live work cannot become a zero-spend terminal. Actor-replacement and zero-run fences exclude `review_owned` runs, which belong to review custody, while settlement, money, containment and registration see all runs.

**Continuation** (`delegate_continuation.py`): `continue_from=<run_id>` starts a new run, cap and key bound to a settled run. After unsupported live input, wait for settlement or cancel and verify settlement before continuing useful retained work. Cancellation preserves partial artifacts, not a finished verdict; continuation may repeat work. How the new run remembers the old one is the engine's choice (`continueFrom`; `continue_carrier=packet` forces the re-brief), reported back as `continuity`. Four floors refuse typed from durable custody: own task line through recorded relations (never room or folder equality; a review panel's run is no task's), settled and not already continued, no pending-ambiguous apply, access not wider and a writer’s target unchanged. Continuation facts (cause, an unread result, another route, a changed work order) travel in the started payload and the child's `prompt`, never `instructions`, which a resumed session may keep from its first request. A continuation is the mind's own start, not recovery.

**Execution evidence.** `delegate_evidence.task_execution_evidence` projects the custody rows read-side. `delegate_start_attempted` counts blocked and uncustodied attempts too, so a refused-but-obedient nanny is never disclosed as nudge-ignoring. `applied_access_profiles` is read off SETTLED rows only, and empty means no receipt disclosed it; an absent `acceptance_patch_dispositions` section means no disposition was recorded, never "reviewed clean"; an unreadable custody log is the typed `evidence_read_failed` marker, never an empty-therefore-clean section.

**Work orders.** The compiler (`subagent_work_order.py`) sends the entire chosen assignment with no host-size cutoff — the normalized host contract once in `instructions` (`delegate_start_instructions.py`), the assignment in `prompt` — and a real native or HTTP limit returns its actual failure. Incomplete source coverage never authorizes a terminal PASS or an apply (`delegate_source_coverage.py`).

#### Supervision, activity and recovery

**Supervision.** `delegate_supervision.supervised_wait` renews bounded transport windows without LLM calls; a meaningful event creates a coalesced durable wake replayed until ACK, while deadline, ceiling, budget and cancel remain outer rails. Read-only `coordination_context` supplies intent, time, spend, descendants and acceptance capacity for the model's judgment, never thresholds (BIBLE P5). Polls are read-only of task state (the usage reader's bounded maintenance: §1 Platform substrate); `observation_read_timeout` means our bound expired against a live daemon, `daemon_unreachable` that no socket answered. Wakes retain full tools; `leaf_live_input` is route capability, never liveness; only `nanny_pacing.BASELINE_RESET_TOOLS` reset burn, so coordination buys no metered silence.

**Delegated activity.** `delegate_activity.py` keeps the executor's message, thinking and problem parts typed in additive `progress_meta.delegated_activity`; host observation (`narration=False`) proves neither nanny authorship nor execution. `gateways/claudexor_run_events.py` reads `GET /v2/runs/:id/events` as bounded SSE keyed by run_id/seq, without a poll or retry loop. Each record's redacted range is retained under `source_handles/delegated_activity/` bound by size and digest, with truncation disclosed (`cuts_truncated`, `seqs_truncated`). Task-file `?source=` reads: §4; UI and replay: §3.

**A run's question belongs to its nanny.** A new `pendingInteractions` entry wakes supervision as `waiting_on_user`; `delegate_answer` echoes the custody keys, and a question beyond the nanny's authority escalates to the nearest live ancestor. `continuation:same_session` is paid per turn. A route without mid-run questions ends `input_required`; the answer is `delegate_start(continue_from=<run_id>, prompt=<answers>)`, never an engine rerun outside task custody.

**Recovery is exact and cause-specific, not generic task resurrection.** A proven non-signal worker crash or a planned self-restart’s typed handoff lets a successor adopt the exact run or pending invocation before any model call or new start; anything ambiguous returns typed recovery-required, never a duplicate mutator; owner restart, panic, signals, deadlines and cancellation are explicit no-resume causes (`delegate_recovery.py`). When no physical run exists and none can be started, the model may finish only with a typed zero-run receipt (`verify_and_record`) after custody proves nothing is open. A session actor’s clean terminal requires its own physical leaf or that receipt; a completed host child cannot substitute. An unknown-provider hold (`delegate_hold.py`) parks the nanny in the supervised wait and never resends.

#### Dispatch, route health and history

**Configured dispatch is exact.** `subagent_runtime.resolve_configured_actor_dispatch` checks live availability at dispatch; a bad choice returns a typed cause, alternatives, reset time and `host_fallback:false`, never host ranking, first-healthy selection or session→API conversion. Selecting `agent_session` is the parent's LLM choice of harness execution: the host sets the truth, money and authorship floor, the model owns topology, decomposition and supervision (BIBLE P13/P5). For a configured subagent every fallback is an explicit LLM-selected start: a pinned selection whose delegate tools are invisible is blocked, not substituted.

**Route health.** `subagents.route_health` is the one health reader for dispatcher, nanny and review slots, and it does not guess admission: the doctor `status` describes only the default credential store while the real accounts live in the engine's credential-profile pool, so admission is the engine's, whose start POST answers an empty pool with a typed `credential_pool_exhausted` at $0. Only a disclosed `resetsAt` makes that refusal a timer-healing window. `enabled` is honored as `route_disabled` (the owner's switch, not an observation); the other structural refusals are the capability catalog, an access-profile mismatch, the delegated marker floor and positively proven quota exhaustion. Review slots inherit "the engine decides", never a silent fallback onto metered API spend. The model sees a facts-only catalog (`model_visible_subagent_catalog`).

Helper observations are history, not routing: `state/subagent_last_delegation.json` (`subagent_history.py`) feeds runtime context and the UI, never admission. A fallback's success never certifies the failed route, nor does a code or test failure condemn a provider.

#### Snapshots, capture and disposition

**Private execution snapshots.** Native/API `external_workspace` children share the target; for them `integrate_subagent_patch` only verifies and records a verdict at the child's own target under the caller's current read, Presence and task policies, with no tree or index write and no transfer into the parent's folder (`applied=false`). `self_worktree` children get a private `workspace_copy` of the selected Git source’s eligible files, uncommitted inputs included, with a task-owned branch and retention. Parents change only on explicit `integrate_subagent_patch` under their current write/Presence authority. Delegated Git runs use separate detached snapshots pinned by `refs/ouroboros/delegated/` and registered in `state/subagent_worktrees.json`; explicit disposition or custody-checked startup GC removes them, and unreadable custody blocks GC. A collected snapshot refuses `execution_snapshot_missing` (registration and retention: [PERSISTENCE](../PERSISTENCE.md)). Nested Git directories are excluded and disclosed; baseline construction vetoes credential-shaped files before hashing (`workspace_patch_capture.py`). `scope.root` is read-only authority; `execution.workspaceRoot` plus the typed binding, persisted before POST, names execution writes.

At terminal, `delegate_wait` durably captures the diff against the recorded baseline into task artifacts (committed bytes carry a disclosed `head_moved`); only explicit `integrate_delegated_patch` apply/reject disposes it, or a continuation that takes the snapshot over. The staging substrate differs: a Git apply proves every touched path still matches `baseline_sha`, then applies and stages without committing. A SKILL-PAYLOAD target captures through the payload adapter and the parent-owned trusted index, applies live, creates no payload Git or index state, and queues the extension reconcile request. Protected-path gates cover only the Ouroboros body. Proven drift is the running nanny's conflict. A durable `delegate_run_patch_apply_started` precedes mutation; an unfinished intent yields `INTEGRATE_DELEGATED_APPLY_AMBIGUOUS`, requiring explicit `acknowledge_ambiguous=true`. `patch_verdict.py` alone writes both pipelines' `run_<rid>` verdict subjects (§1).

**Terminal products and their reader.** Reconciliation calls `delegate_integration.capture_terminal_patch_for_drive` for settled mutating runs and never applies; only a ready manifest earns `patch_captured`, and missing run evidence keeps the snapshot because writers may live. `delegate_custody.undisposed_patches` belongs to run and target beyond the creator's lifetime until a durable `PATCH_DISPOSED` names `disposed_by_task_id`.

The starter retains live control. `delegate_shared._confirmed_retry_chain` grants settled-product access only to the current automatic retry leaf; shared roots, predecessor prose, stale evidence, review-owned runs and `CLOSED_ABSENT` grant none, and manual Continue grants none of it. A successor's `delegate_wait` uses `retry_terminal_result`, never live supervision, cancel, answer or message.

A writing continuation runs in its predecessor's undisposed snapshot: its STARTED row replays the predecessor as `superseded` — never applied or rejected alone — and the one cumulative patch is integrated once under the snapshot's single disposition lock. The unrelated live top-level orphan path only after proven owner terminality: apply requires exact active Git root/fresh payload binding or host-minted project containment (`<project>/contributions/<track>`); reject needs no fresh target grant, so a live top-level task with a different active root may reject and release another dead task's snapshot. Missing, unreadable or unreaped owner facts retain custody without expiry.

**Custody disclosures heal from the write side.** Custody debt is a warning beside the earned rail, never a replacement of it: `delegated_custody_unreconciled` covers the task's own undisposed runs and `outcomes.custody_debt_axes` adds the warning without replacing earned axes. Readers never replay custody: the audit writers in `delegate_terminal.py` refresh the stored facts, unknown clears nothing, and frozen `delegated_runs_*` counters stay while `actual_substrate` follows live custody. Provider death plus debt stays Failed with the custody reason; clean plus debt does not increment `evolution_consecutive_failures`.

Disclosed delegated-isolation residuals: an orphan disposed by a non-owner writes its verdict under the disposer's task while the capture directory and the `PATCH_DISPOSED` row keep the owner's id, so the owner's acceptance packet will not list that verdict; the Git lock is task-drive scoped, so two nannies integrating into the same external tree can interleave, and the drift check turns the loser's apply into a typed conflict; a credential-shaped file the child creates fails the whole patch rather than shipping a partial diff.

#### Access disclosure and accounts reads

**Native access disclosure.** Full access has no filesystem sandbox; snapshots own delivery. `CLAUDEXOR_DELEGATED_MARKER_MIN_VERSION` is a schema floor: `route_health` blocks incompatible mutating requests before token spend; read-only delegation omits the marker. Isolation follows attempt evidence, never platform or version. Missing containment is disclosed as `delegate_run_unconfined` without refusal because the child already has native shell access. Recorded `harness_home_isolated:false` or a claimed isolated HOME equal to the operator’s cancels as a breach; nested HOME is disclosed-unconfined and missing HOME evidence stays unproven. Applied-evidence readers, threat model and floors: `docs/DELEGATED_ADMISSION.md`.

**Delegated authority cannot widen.** `delegate_start` exposes only `prompt`, the session `subagent_id`, `max_seconds`, lowering-only `access`, `retry_of`, `continue_from`/`continue_carrier` and the payload selector — no mode, isolation or scope argument. Retry preserves route, root, access and permissions; host instructions are unforgeable; native process access never overrides task constraints or the assigned edit target. Every fetched detail passes `_containment_breach`, which checks both access and harness HOME because Claudexor derives effective access rather than echoing the request: wider access cancels as `access_profile_widened`, narrower is valid.

**Read provenance on the accounts surface.** Status-read provenance (`reads`): the §1 `gateway/claudexor_accounts.py` row; routes: §4.

### Own-body candidates

Ordinary authors of the body — a queued root, a direct turn, an evolution cycle — write a task-owned linked worktree of the serving repository, never the checkout the server imports (`body_candidate.py`). It starts at the serving HEAD commit, not the tree's dirt, on branch `candidate/<task>` under the isolated worktree root, and is a `kind=body_candidate` row of the worktree registry: that row restores the binding for a retry, a Resume or a new worker. `prepare_self_change` prepares it explicitly before process-first work; a body file write, a PR-integration verb (`git_pr.BODY_WORKTREE_TOOLS`; its integration branch starts from the body's working branch) and an acting `self_worktree` child reach the same preparation through one dispatch seam before any target is resolved. No command text is classified, and reads before preparation stay on the serving tree. Light mode, capped trees, subagents and the managed-update resolver get none; Cyber Pro may choose `in_place`; a body with no Git tree keeps in-place authoring.

Binding rewrites one fact: `repo_dir`, `system_repo_dir` and `branch_dev` of the tool context name the candidate, so target resolution, mode and protected-path guards, handlers, process cwd, review subject (`review_repo_dirs_for`: the candidate even when the task also carries a workspace root) and `commit_reviewed` share one identity and keep own-body policy — it is never an external workspace. `serving_repo_dir` keeps the running checkout for review governance, the restart marker and rollback. A child of a bound parent receives the candidate as its `self_worktree` source, including an explicitly selected serving root (relative or symlink aliases included), so its patch returns there. File paths inside patch and batch-edit payloads use the same serving-alias normalization as single-file edits. A process whose cwd is inside the candidate or its admitted own-body child copy gets `test_environment.isolated_environment` rooted beside it (`<candidate>.env`): own HOME, data, settings, caches, and the test environment's scrub — no `*_API_KEY`/`*_TOKEN`/`*_SECRET` values, no `GH_*`/`GIT_*` or global Git config, no inherited `OUROBOROS_*`, `OUROBOROS_PYTEST_ACTIVE=1` and `PIP_REQUIRE_VIRTUALENV` — so a push, a provider call or a pip install outside a venv runs from a cwd outside the candidate; local executors replace their inherited environment; Docker commands and services use a cleared environment with backend paths and require a mapping covering both the copy and its sibling `.env` directory. When that environment cannot be prepared the process is refused (`CANDIDATE_ENVIRONMENT_UNAVAILABLE`), never started with the serving environment.

Ownership is the root task. A host-validated continuation inherits its predecessor's candidate and `prepare_self_change(resume=…)` selects one exact retained candidate; either moves ownership only from an owner whose task record is terminal AND whose indexed ledger and executor records for that root, its effective retry chain and their recorded children are settled (`live_lineage_processes`; a corrupt set or an inconclusive matching process record is not quiescent). Nothing is inherited by room, name or date; each independent direct turn owns its candidate, and the Runtime block lists retained candidates. Binding appends the candidate to the lineage's mutation baseline as a late surface (a taken-over candidate names its previous owner as the predecessor whose quiescent changes are adopted), so `commit_reviewed` stages what the task's own baseline attributes to it exactly as on the serving checkout; without a host baseline the explicit/whole-tree contract applies as it does unbound. The commit is never auto-pushed, and each gate-created SHA is recorded on the row. A candidate commit takes P9's version-neutral form (VERSION untouched, every carrier span byte-identical to HEAD, no tag) or a numbered release (VERSION and every carrier in one diff, tagged); the deterministic release gate names the form from the diff and reports a partial carrier move as neither — on the serving checkout the standalone lane still requires the numbered release. Documentation-only changes also preserve every declared carrier span; ordinary prose remains exempt. Retention counts from last use: clean candidates remain until expiry; nested `OUROBOROS_RETAINED.txt` markers retain the process environment and source checkout, including when they appear after the initial GC verdict. Unadopted commits are compared to the serving checkout’s HEAD, even when it is a linked worktree. A candidate with no unique work expires; otherwise its tracked, untracked and ignored files (static env/cache directories and runtime junk excepted — a plain file merely named like one is the author's) are captured on `refs/ouroboros/candidates/<id>`, a version staged but not on disk as its own parent commit, and the checkout is removed only if that capture is complete — an incomplete one keeps the directory. The worktree GC computes that verdict outside the registry lock and applies it under the lock only while the owner remains terminal and quiescent, the row and path set match, and a preserved snapshot's staged index and file bytes are unchanged (`verdict_holds`).

Adoption is deliberate and restart-bound (`body_adoption.py`): `request_restart(adopt_commit=<sha>)`, or an evolution cycle's own restart, authorizes one exact commit that builds on the serving HEAD, came through the commit gate (Cyber Pro records the exception), keeps the entry files and the package-init hook, and meets a clean switch set; a constitutional change needs a numbered release outside Cyber Pro. Authorizing pins the commit, captures the switch helper outside the tree and writes the handoff; the old generation never writes the tree. The restart that carried it re-verifies under the update lock, and its exit tail arms — publishes the Git-dir pointer — only on the stop owners' own evidence: the worker pool's PID census of the kill that just ran (`supervisor.workers.last_worker_exit_census`, every doomed worker confirmed dead; the kill's boolean is about cleanup, never a reader census), `stop_owned_work` completed with no currently registered stop target and no live multiprocessing child; the owner's Restart and Panic never arm and never wait. The same exit tail compares the engine pin the NEXT generation selects — the bound candidate's file when the switch changes it (`bound_candidate_file`) — before stopping the owned daemon. Evolution cleanup abandons only its own task/candidate authorization. Crash recovery retains a reviewed candidate without authorizing adoption: the existing status names `prepare_self_change(resume=…)` and `request_restart(adopt_commit=…)` for deliberate continuation, with no automatic scheduler. The switch and its recovery are §2; `settle_on_boot` records `adopted` only for a generation whose process attested the switched tree before its imports, whose bootstrap (dependency sync and import test) succeeded and whose supervisor is ready, with the native-host readback where one applies, and reports every authorization that was not applied.

### Git and commit review

`pr_merge(number, expected_head_sha, method)` uses the selected repo's `gh` identity, exact head, no force/admin/auto. `merge_receipts.py` claims task-owned intent before effect; locked writes keep stronger settlements and attribution. Unknown/queued merges are observation-only (CLI exits, transport loss, 5xx prove no rejection); only proven pre-effect failures release intent. Reviewed facts come from the host record named by `review_record_id` (`review_ledger.load_record`: subject kind/base/head/tree, verdicts, panel size), else a `declared_only` declaration; a missing record refuses pre-effect as `arguments`, an unreadable one as `review_record_unreadable`. Recovery compares requested/reviewed/current/merged head/tree/base: an `index`/`worktree` record (`subject_kind_not_committed`) or another base (`reviewed_base_differs`) never `covers_head`; body and card name the source; a record reads green only when settled PASS. Missing review is loud, never a veto. Canonical receipt revisions key outbox deliveries and the card's monotonic live/history projection. PR bodies use fresh read/REST PATCH/readback via the same `gh_api` identity at the recorded PR URL's host/repo/number (no `gh pr edit` org queries/extra scopes), catching canonical advances; lacking GitHub body CAS, concurrent edits can race PATCH. Receipt persistence and body/card publication gaps (incl. unknown targets) reach callers; confirmed merges stand. Shell/web merges lack receipts.

`tools/git.py` owns repository writes, staging, reviewed commit, rollback or restore, tags, push and CI follow-up; its leaves are `git_plumbing.py`, `git_repo_edit.py`, `git_vcs_ops.py`, `git_review_cycle.py` (staging plus the optional preflight, the one review wave and the reviewed-material binding the commit gate consumes) and `git_evolution.py` (campaign authority at the reviewed-commit and publication boundaries). File-edit tools validate their own atomic write shape. `mutation_attribution.py` captures the root-task baseline and projects the clean-at-baseline system-repository delta plus an explicitly adopted predecessor's exact retained changes — a changed pre-existing dirty path, a stale or missing baseline, or a failed scan blocks automatic staging; `commit_reviewed(paths=None)` stages only that attributed candidate, explicit paths must be a subset, an empty candidate returns `GIT_NO_ATTRIBUTED_CHANGES`, and managed update transactions keep their separate typed whole-tree authority. At startup a later independently initiated task may adopt exact retained candidates from its host-validated predecessor source in the same repository. `predecessor_adoption` preserves the observed dirty baseline and original source; terminal quiescence, unchanged path content and unchanged per-path base are required, while unrelated dirty work stays excluded. Missing fingerprints or size-only observations establish no transfer, and adoption grants no review approval or automatic new task. Commit preparation verifies the exact local working-branch ref before an unambiguous checkout: a missing ref refuses without changing the current branch, index or files (remote guessing and implicit branch creation are disabled), detached work retains the `checkout -B <branch> HEAD` recovery, and managed assisted merges retain transaction-owned precommit verification.

A reviewed commit is bound to one staged fingerprint. The author may name one row for an early look first (§6 "Commit preflight"); the look or its absence never changes independently applicable tests, the review wave (both questions), aggregation or exact-SHA binding. The hermetic preflight runs the candidate in a disposable worktree and data root; every seat of the wave inspects the same staged snapshot, aggregation preserves actor evidence and obligations, and any mutation stales the binding. Managed exception: a managed-update resolution commit reviews the declared M0→S subject (`tools/review_subject.py`) and the commit gate binds S to the exact index write-tree the fingerprint pins. External review wrappers report readiness, never commit authority. The exact binding includes the `git write-tree` SHA, ordered `HEAD` and `MERGE_HEAD` parents, indexed VERSION, expected `v{VERSION}` tag, any existing tag target, and the binary staged-diff hash; after commit, tree, parents, VERSION and tag target are re-read before success or push is recorded; an existing release tag is never silently accepted or retargeted. `release_sync.sync_release_metadata` projects version carriers during ordinary commit preparation; `VERSION_CARRIER_SPANS`/`substitute_carrier_spans` is the ONE span primitive the managed-update resolver and the commit packet's carrier cut share, and `carrier_only_change` names a carrier changed only inside its declared version spans. Durable review state keeps attempts, obligations, readiness debt, raw actor evidence, and the final commit or tag binding; a preflight's full answer lives in its own `surface=preflight` ledger record, while `review_status(include_raw=true)` exposes the wave's raw seat attempt evidence; `commit_gate.py` classifies review blocks, refuses an identical verdict, counts paid cycles against the ceiling and fingerprints the review contract. BIBLE supplies review authority, CHECKLISTS criteria, Development the procedure; snapshot identity, the preflight fact, deterministic results, actor evidence, and final Git identity must all describe the same material.

Material ordinary Advisory commit review returns the complete outcome and exact `review_reference` before commit, tag or push. The author may correct, accept unchanged bytes, request another permitted review or stop. Explicit `commit_reviewed`/`vcs_commit_reviewed` continuation with that reference and `author_disposition` binds the current attributed candidate, reruns independent required preflight/tests and exact Git checks, and dispatches no critic. The author record references the original attempt instead of rewriting its subject or paid facts. Settled handback is `reviewed/review_only`; actual pending custody remains `reviewing/late_wait` and collectible. Clean supported review keeps its one-call path; Blocking gets no author override. Evolution receipts record the wave's actual aggregate (`triad_scope_status`), never infer PASS from a successful Git commit.

#### Hermetic preflight proof

The hermetic runner (`preflight_runner.py`) alone mints `ctx._preflight_test_proof`, after actual green lanes and containment; it binds the assembled checkout tree and installed index, effective pass specs, isolated environment (`test_environment.py` owns writable roots), and the invoked/resolved interpreter and active Node identity (a Python symlink's invocation path selects its venv). The candidate is ONE hardened raw-bytes `git diff --binary … HEAD` capture (a staged+unstaged diff pair cannot faithfully materialize unmerged entries); a capture/apply failure is the typed `PREFLIGHT_CANDIDATE_ASSEMBLY` block, never a test verdict. The node lane runs first (`preflight_node.py`: bundled signed node then PATH, floor 20.11; `PREFLIGHT_NODE_MISSING`/`PREFLIGHT_NODE_TOO_OLD` hard blocks and `NODE_TESTS_FAILED` on a red suite, never a silent skip), then the two-pass parallel/serial pytest split under one budget (`LANE_EXCLUSION_EXPR` is the marker-lane SSOT); a dead xdist worker or a missing required plugin is a distinct named block, never a retry or silent serial fallback. Equivalent ordinary and managed checks reuse that process-held proof only after their distinct baseline checks; a phase label alone cannot establish equivalence. Every workload binds HEAD, since even an unmarked default-lane test may inspect committed files or history: repeated preflights reuse an unchanged subject, a new commit changes HEAD and needs a new run, a skip or no-suite `None` is no green proof, and a restart loses the proof and reruns. Creation and reuse emit `preflight_test_proof` observations through the existing event log, naming the task, HEAD, tree, index and workload fingerprint; an unavailable log yields an explicit diagnostic, never a test failure or new authority source. Managed `tests_evidence` is forensics, not reuse authority. Unproven lane teardown retains the temp tree and Git registration (`_release_hermetic_tree`), raised lanes included; deleting inputs under surviving processes would destroy custody.

#### Commit preflight

`preflight_review(commit_message="...", deterministic_only=True, source="worktree" | "index")` returns free diagnostics before sync, staging, review-state access, provider checks, tests or fingerprints. `commit_admission.release_metadata_diagnostics` acquires the selected source and `release_sync.release_metadata_findings` evaluates its current VERSION, carriers and P9 limits. The release report identifies its source, status (`clean`, `blocked`, `unavailable`, `not_applicable`) and findings; it grants no review freshness and writes no history. A separate `book_balance` field labels its bytes as worktree and uses `reference_books.py` to show the cached official development merge-base or unknown contribution. Book growth never changes the release status or blocks a local commit; syntax, tests and critic review do not run here.

The author's preflight is one look, not a pipeline: `commit_reviewed(preflight_reviewer="<row>")` names ONE enabled catalog row by id or handle, a review-pool member or not — an unknown or disabled row is a `TOOL_ARG_ERROR` before staging (`commit_gate.preflight_reviewer_error`) — and after the free checks and the tests the gate runs `review_change(subject=worktree, surface=preflight, reviewers=[row])` on the system repository (`commit_gate.run_commit_preflight`), before the wave. The look informs and never gates: its `surface=preflight` record carries the surface in its reuse key, so it never answers, reuses or replaces the commit panel's record, and the commit record's `preflight` fact names it (`performed` with `record_id`, row and aggregate; a refused or crashed look stays `performed` with its cause; `BudgetExceeded` propagates). Without the argument the fact is `not_performed`, a plain fact rather than an audited bypass; `skip_advisory_review=True` records `skipped`; naming a row beside `skip_advisory_review` or an author continuation (which dispatches no critic) is a `TOOL_ARG_ERROR`. The look reads the live worktree, counts against `review_change`'s paid-cycle cap and holds no commit custody (its wave froze its own tree). The checkout's newest `surface=preflight` record (`review_ledger.latest_preflight_record`) is the look `review_status` reports: a worktree mutation after it writes the stale marker (`AdvisoryReviewState.mark_look_stale`, the first editor after the look named, later ones not), a marker older than the look does not stale it, and a live tree that differs from the one the record bound reads `stale_from_edit` with no editor; `review_status.preflight` names the record, row, aggregate and both facts. The free checks that preceded the retired advisory delivery run on every commit, a skip included (`commit_gate.deterministic_preflight`: size headroom and readiness as information and warnings, release metadata of the staged index, staged `.py` syntax). The tests preflight keeps the advisory's rule for every commit, a named look or not: the suite runs unless `skip_tests` (a documentation-only diff included — documentation has tests too), and a managed resolution always pays it. `preflight_review(reviewer=…)` (`tools/preflight_review.py`, `advisory_review` alias) is the same look standalone: no tests, no release-metadata sync.

The reviewed-commit cycle (`git_review_cycle`) checks authorization and unresolved prior work before mechanical preparation and staging, binds the exact candidate before free-cycle/budget admission, runs the checks, applicable tests and any named look inline with the full rebuttal, and revalidates the index and worktree snapshot before the wave; it owns entry-point resets and pending/blocked finalization, and its custody check (`_review_custody_pending`) reads the panel's own reviewer facts before index cleanup. Legacy advisory rows in `state/advisory_review.json` are history only: no writer remains (`add_run` is gone), the mutation marker may still stale them, and they hold neither admission nor commit custody; no surface projects a `repo_commit_ready` readiness from them.

A legacy `AdvisoryRunRecord` keeps its recorded `execution` identifiers for inspection only: `review_status` projects them through the public secret redactor, and nothing rejoins, discharges or replaces them. A named look's custody, retry and late result are those of its own `review_change` record (§6 "Review ledger record"). The external wrapper's operator lane runs the same cycle; with `--preflight-reviewer` it writes the look's `surface=preflight` record to `preflight.json` and the reviewer's full answer to `preflight.txt`, and it preserves a pending checkout without restaging.

### Review stack

`review_cycles.py` owns the shared paid-cycle ceiling `OUROBOROS_REVIEW_MAX_CYCLES` (a positive integer or `unlimited`; anything else fails closed to the shipped default). One number, four gate meanings: paid reviewer-panel cycles per task for plan review; paid panel runs per task for acceptance, independently of ordinary author responses; paid review waves per ROOT task for the commit gate, counted from the attempt ledger at DISPATCH so the ceiling counts money and only undispatched attempts stay outside it; paid panel dispatches for skill review. Byte-identical material replays each gate's recorded verdict for free under that gate's identity. Physically dispatched technical failures consume capacity; undispatched refusal and collection do not. The last allowed panel still permits author reaction. An explicit task-local `max_improvement_passes=p` retains its p author responses and p+1 paid ceiling; without that override N creates no N−1 response limit. `unlimited` removes only the paid count, not ordinary task rails.

For skill review, reviewer convergence guidance and the author retry note (shared with commits; it owes an outcome, not a procedure, and is not contract identity) use the group's `review_round`, so revising payload bytes does not reset them. `snapshot_attempt` remains the separate ordinal shown in history and headers; free replay keeps its exact material and contract identity. A paid-ceiling refusal names author finish only where the existing enforcement predicate permits it.

Review waiting has six independent axes:

| axis | bound |
|---|---|
| transport | dead-socket read bound |
| operation | typed active-operation lease |
| logical | slot/task deadline |
| policy | budget / cancellation |
| absolute | task ceiling |
| aftermath | late-result custody |

#### Physical custody

`review_custody.py` owns physical workers under `review_substrate.py`, with no task scheduler or second timing ledger. Independent operation ids and the live map prevent in-flight work from appearing idle; deadline, budget, cancellation and ceiling still bind. Delegated expiry uses verified cancellation; API/thread calls disclose `in_flight` and collect late answers before retry. Settled terminal API errors remain replayable, so siblings cannot erase them or duplicate dispatch.

Capture state proves custody, never a synthetic id: only `reserved|released` proves pre-dispatch; positive capture outranks conflicting labels; `dispatched|unresolved` without terminal HTTP status remains custody-lost/no-resend (`usage_accounting`). Only explicit `__cause__` or typed transport metadata proves pre-dispatch, not inherited Python `__context__`. Delegated retries require durable invocation tokens matching surface/slot/operation. Explicit material/cycle retry identity excludes mutable prompt/history; changed snapshot, owner intent, route or admitted cycle creates a new identity.

Timeouts narrow to owner deadline/finalization reserve: VLM's 90-second and Anthropic's 120-second provider defaults are not generic review-reasoning limits. Returned responses and typed terminal errors settle even if empty, permitting bounded repair; post-dispatch socket death is `provider_outcome_unknown`, never another paid route. A spent owner window refuses at $0 before fan-out. Blocking in-flight seats remain pending; primary deadline expiry uses `deadline_local`, not provider-outage labeling. Reviewed commits have no separate outer tool cutoff: foreground custody lasts to settlement.

#### Paid stamp and owner custody

The `paid` fact behind the cycle ceiling is recorded WRITE-AHEAD at physical dispatch (`review_dispatch.py`): a gate installs one once-only `ReviewPaidStamp` for its wave, and each delivery stamps at its own boundary — a packet api row at the usage ledger's physical-attempt transition, a native episode on each paid send, a session before its replayable `START_REQUESTED` row. Assembly-only refusals exit before that seam, so a $0 attempt stays outside every ceiling, and neither a worker outliving its logical caller nor a crash after dispatch can lose the durable fact. The stamp is idempotent across the wave's concurrent deliveries (packet and retrieving seats), so no seat's transport starts before the paid fact is durable; commit review and task acceptance treat a failed write as fail-CLOSED, skill review only when resuming a wave, other callers keep fail-open accounting. Task acceptance binds a strict exact-hash tree-wallet claim to that same stamp on every delivery its rows run — one idempotent claim per panel, because the paid identity is material, not route; a wallet or cancellation veto at the claim releases the reservation and no reviewer transport proceeds on any row (the launch floor is evaluated once, at loop admission: §6 Task lifecycle). Disclosed residual: a compatibility transport that raises with positive physical capture without having entered the canonical marker is stamped after the send; if the tree's last paid cycle is consumed concurrently at that late stamp, the wallet refusal replaces the captured exception and the substrate may resend.

Before the wave starts, one locked write records `paid=True` plus the wave's complete reserved seat roster and operation ids in the commit-attempt row; a delegated slot patches its reserved row with `pending_invocation_id` before the provider POST. Exact resume preserves rows and tokens; a missing or mismatched operation is `custody_lost` under every enforcement mode. The stamp records the process-custody server session and pid owning the reviewer threads (`review_owner_custody.py`): owner-loss is proven by pid death, never elapsed time — a TTL would convert waiting into resend authority, and starting another Agent is not evidence this owner died. Tokenless rows settle as typed infrastructure failure only after a death seam confirms that exact pid gone, and a legacy row without owner identity stays fail-closed. Plan review re-enters a recorded in-flight cycle only through exact live custody or complete operation-addressed CAS for its recorded dispatched rows; a delegated poll that loses transport after a run id exists preserves the exact durable invocation for retry custody rather than cancelling a healthy unknown run.

Per-row delivery is a property of the catalog row — `delivery: native | packet` on an API row, while a session row always retrieves — read by `reviewer_slot_config.review_pool_slots` (`ReviewSlot.native_retrieval_override`); the older per-row route envs are retired and ignored. The one shared session target is `OUROBOROS_REVIEW_SESSION_ROUTE` (`review_execution.REVIEW_SESSION_ROUTE_ENV`), an opaque `harness[=model][:effort]` spec that falls back to `OUROBOROS_SUBAGENT_HARNESS` when unset, so one delegated route is configured once; a set but unparseable value turns review sessions OFF with a warning rather than silently re-routing them onto the subagent route.

#### Surfaces and money admission

The review surfaces:

- Preflight (`review_change(surface=preflight)`) — the author's optional one-row look before the panel (§6 "Commit preflight"); it informs, never gates and never answers the commit panel.
- Change review (`tools/review.py`) — the review pool's seats cover the layered Change Review Checklist (the universal core, plus the Ouroboros Body Layer when the subject is the body — `review_helpers.load_checklist_layers`) with JSON findings under `config.adaptive_quorum` (the same SSOT as plan/skill/acceptance review). A packet seat answers contract A (`triad_review.REVIEW_JSON_ARRAY_CONTRACT`, the findings array); a retrieving seat answers contract B (`REVIEW_TWO_PART_OBJECT_CONTRACT`: `{change, change_clean, coupling}`) — one wave, two questions, one quorum over the seats that answered (`review_ledger.reduce_verdict`, shared by the gate and the record).
- The coupling question (`tools/review_brief_coupling.py`, Part 2 of the retrieving seat's brief) — intent/scope/coupling across the whole repository, asked of every retrieving seat of the same wave (there is no separate scope role); the exact candidate, required-source manifest and diagnostic reading coverage stay distinct from substantive findings and configured enforcement (§6 The coupling question).
- Parallel orchestration (`tools/parallel_review.py`) — two-phase admission: the api packet is assembled/fit-checked and every retrieving seat's two-part brief built before any reviewer dispatches, so a deterministic assembly block anywhere dispatches nothing and spends $0 (a lane paid while its sibling was doomed is real money for a half-verdict). Money admission (`tools/review_admission.py`: `commit_gate_paid_seats` / `admit_commit_gate_wave`) admits the wave while KNOWN spend is below the global `TOTAL_BUDGET`, current root and original billing-group fences: every PAID seat of the one wave (packet or retrieving) is priced, as disclosure, with the reservation math `reserve_attempt` will apply (exact first send, native work-order and tool schemas included, plus its own output reservation; later native rounds reserve themselves), under its substrate's usage scope (`review_usage_category` + slot, so a warm split of the caller's transcript never stands in for a seat's cold prefix). Admission uses the reservation's `_merge_scope` resolution, including missing durable group bindings and explicit owner amendments; a raised root cap alone never raises its group — and admitted as ONE wave through `review_wave_budget_gate(surface="commit_gate")`. A refused wave records typed `$0 not_dispatched` on every seat plus one `review_wave_budget_insufficient` event with `binding_axis` (`global`/`root`/`group`) and the remainders; the block names the fence and actual remedy. Admission is a read-only pre-check without a wave-level hold; per-seat reservation and dispatch stay the enforcement, so a fence that known spend reaches mid-wave refuses the remaining seats with truthful custody. A paid seat is any api row (packet or native episode); an agent-session row rides the owner's subscription (ledger row written at settlement, never reserved) and is neither priced nor waited for. Every executor transition toward a seat runs under `contextvars.copy_context()`, so reviewer rows reserve under the admitted usage scope, bound root fence included; a mid-turn settings reload of the per-task limit changes neither side. An admission that raises is fail-open like the gate's own unknowns, but loud and typed (`review_wave_admission_unavailable`; the wave dispatches unadmitted). An admitted wave submits every seat together, with no lead seat and no hold. Admission touches no transport or logical timeout contract.
- Shared helpers (`review_helpers.py`, `triad_review.py`) — packet/brief building, checklist loading, JSON extraction, usage events, obligations scaffolding and reviewer actor records.

A free refusal never wears the form of a verdict: one that spent nothing is recorded as a typed `not_dispatched` fact plus its reason, never as a DEGRADED panel or a synthetic actor. That is the one shape across every $0 exit — a plan-review locator the evidence policy cannot attach is a named omission row the panel is dispatched with, an acceptance packet that overflows takes the ladder rather than reporting a verdict, a truncated or self-pageable row names its cut, and a request never sent is one seat with `operation_state='not_dispatched'` that stays in the denominator. `task_acceptance_review` refused before dispatch (a child with no selectable row, an invalid roster: `status=not_dispatched`, no run/actor evidence) stays a tool result outside `review_runs`; alone it cannot degrade the review axis. Dispatched malformed, overflowed or degraded results still do (`loop_tool_execution.process_tool_results`).

Part 1 catches line errors; Part 2 catches cross-module contracts, from the same seat over the same staged snapshot (managed updates: M0→S), so one answer cannot hide the other. Task acceptance, owned above under Task lifecycle, shares quorum/transports, asks no coupling question and stores its verdict separately from the terminal result.

One pool, many subjects — who calls the wave and what each seat is asked:

| subject | caller | questions |
|---|---|---|
| the body's staged index (a commit) | `commit_reviewed` — the gate | every pool seat: the change part, and the coupling part on every retrieving seat; in Cyber Pro the panel is composed from the pool and the reason recorded |
| the body's live worktree before a commit | `commit_reviewed(preflight_reviewer=…)` / `preflight_review(reviewer=…)` — the author | one named enabled catalog row, the same two parts by its delivery; informs, never gates |
| any root's `index` / `worktree` / `base..head` | `review_change` — the mind, by judgment | the same two parts; the body layer on the body, the universal core on a foreign root; `reviewers` adds seats on the body outside Cyber Pro and composes the panel elsewhere; `coupling_only` critics `[coupling]` outside the quorum |
| an intention | `plan_task` — plan review | the Plan Review Checklist, every pool row |
| a skill payload | `skill_review` | the Skill Review Checklist, every pool row |
| a task result | `task_acceptance_review` and loop acceptance | the acceptance question only — a root: every pool row, a child: at most one (`reviewer_slot_config.child_acceptance_slots`); no coupling question |
| the running system | `/review` — deep self-review | the deep self-review report, one enabled catalog row (default Main) |

**Council and review are two mechanisms.** A council is children the mind schedules (`schedule_subagent`, `forward_to_worker`) to argue "what should be done" — research, alternatives, adversarial checks — and it runs before a review; a review is the pool's independent voices asked "was it done right" on one exact frozen subject, recorded in the ledger. The mind may call both on one commit: a council's outcome is attached as evidence to the subject, it never becomes a verdict, and no finding is erased by a vote; a helper the mind schedules is never the panel and never wears a seat's name. There is no consensus round and no third organ; the conditions under which that is revisited are recorded here: (a) the action over the subject has landed; (b) blocking installs show in their records "one seat held a critical FAIL while the rest passed, the cycles ran out, the owner decided" — with its frequency and cost; (c) the mind convenes children's councils on intentions unasked, and those intentions then go to the panel; (d) a retrospective shows a class of defects found only in dialogue between reviewers; (e) the blind panel's false-critical share becomes review's main cost. The minimal future form would be an optional cross-check round of the same panel after `review_change` lands — the first round blind, only the raising seat may withdraw its finding, no voting.

**`## Review`.** The mind sees the review pool its task's settings snapshot serves as one semi-stable block after `## Available subagents`, in the shared and the declared-input context alike (`subagent_runtime.review_facts_block`). It is read through the one builder every review surface runs (`reviewer_slot_config.review_pool_slots`) inside the task's settings scope, so a later save changes the next task's block, never this one, and it never reads the last execution (a dynamic runtime fact). It states the `source` — `structured` (a non-empty pool), `empty` (a readable catalog with no marked row: a loud configured fact, `pool_empty: true`, never a default panel) or `error` (a malformed catalog, or the refused migration of this very document — its snapshot still carries the refused lanes key — with the message beside an empty `pool`, never an absent one; a repaired document or another task's snapshot wears no past refusal) — the `enforcement`, `enforcement_blocks`, the runtime `mode` and one `rule` sentence (the execution rule of the effective authority: what a finding or a failed review does to the change — Cyber Pro, Blocking or Advisory); per seat `seat_id` (the stored row id the records carry), `subagent_id` (the catalog handle `## Available subagents` shows and `review_change(reviewers=[…])` accepts), `model`, `effort`, `delivery` (`session`, `native` or `packet`) and a `cost_hint` (an API seat: one full call of its row, the price Settings → Agents shows, from tariffs already cached in the process; a session seat "uses a session seat and time"); and `surfaces` — who reviews where, as text: the commit gate (every pool row outside Cyber Pro; composed from the pool in Cyber Pro with the reason recorded), plan review (every pool row), task acceptance (a root: every pool row; a child: at most one from the pool, named by `reviewer_slot_id` when there are several), the preflight (one enabled catalog row the author names; none → recorded as not performed) and `/review` (one enabled catalog row, default Main). Above four seats rows shrink to `{seat_id, model}`; `omitted.rows` counts them; `coupling_unanswerable: true`, present only when no seat reads the repository (every row Packet: each commit-gate review ends `NOT_PERFORMED`), is a block fact the shrink keeps; `pool_without_credentials` names the api seats whose model this install holds no credentials for (a session seat logs in itself), present only when there is one, and `no_pool_row_has_credentials: true` when that is every seat of the pool — the same fact `GET /api/review-pool` carries and Settings → Agents shows as a note; `migration_snapshot` names the receipt of the migration that decided this document — the finished one whose catalog it carries, or its refusal — when the boot wrote one. `full_source` points at `GET /api/review-pool` (current saved settings, the full pool) and at `## Review records`: the task's five newest review-ledger records (`record_id`, `surface`, `aggregate`, `ts`) ride in the changing part (ids and timestamps never sit in the cached prefix; none without the ledger module); their `omitted.records` count is a bounded fact — the hot index is read once with a six-row cap and the archive is never opened — so it says `0`, `1+`, or `unknown` when an archived segment exists or the ledger cannot be read.

#### Subject operation

The review wave is parametric in its SUBJECT (`tools/review_subject.py`): a `ReviewSubjectSpec` states what is reviewed — the root (`system_repo` or `active_workspace`), the kind (`index` = the root's staged index, `worktree` = its live tree, `base..head` = a committed proposal whose base must be an ancestor of its head), the surface and the checklist layer — and `freeze_subject` pins it ONCE as a `FrozenSubject`: the prompt diff, the identity of the binary patch between parent and reviewed tree (`diff_sha`), the trees themselves and the name-status rows. Governance is ALWAYS the installed body's (`governance_root`: the SERVING checkout, `review_substrate.review_repo_dirs_for`'s rule — a bound body candidate (`body_candidate.bind`) is the subject that is reviewed and the body fact is read against the serving body, never the candidate's own copy of the rules; the gate's and every retrieving seat's rules, checklist and navigation come from it, never from the reviewed root), while the reading root is the subject's. Exactly ONE subject is read on its live root: the gate's own (`is_gate_subject` — the system repository's `index` against HEAD with no explicit base), which goes through the gate's own capture (`managed_review_subject(surface="gate")` / `capture_staged_diff`) so its api pack, two-part brief, seats and gate decision are byte-identical to the gate's. Every other subject — `worktree`, `base..head`, a foreign root's `index`, any `index` against an explicit base — is MATERIALIZED by `isolated_checkout`: a detached worktree at its parent with the frozen binary patch applied to its index, under the install's data root (`state/review_checkouts/<token>/repo`; its `write-tree` must equal the frozen tree). The token is the task's ROUND's (`checkout_token`: a digest of the task id and the custody retry key, identity c below — the subject is frozen first and the path derives from it), so a rerun of the same round on the same task reads the checkout an earlier wave's open custody retained (same tree, read in place, never rebuilt) and its `session_root` is the one the open operation was keyed by; the checkout is removed on exit unless custody stays open. All deliveries read that frozen subject: the api packet and every retrieving seat's two-part brief carry `FrozenSubject.diff_text` (`review_brief_coupling.BriefInputs.diff_text`; never a recapture of a root's index), the `-U0` fit rung is `render_prompt_diff(0)` over the frozen `parent_sha`→`tree_sha` (never a repeated `--cached` of the live root), the required-source manifest is computed against the frozen trees, and the retrieving seats (session and native) are pointed at the checkout, whose staged index IS the frozen patch. `run_parallel_review(subject=…)`, `_prepare_unified_review(subject=…)` and `retrieving_brief_for_seat(path_subject=…, managed_subject=…)` read the frozen diff, trees and roots; `subject=None` is the gate's path unchanged. A frozen subject that is not the body's own index skips the body's release preflight (version carriers, Architecture book rows): the layer `core` is a foreign root under the body's rules, not the body's release contract.

Three identities derive from the frozen subject, never from the live index of whatever repository the process runs in. (a) The REUSE key (`review_reuse_key` → `review_ledger.reuse_key_digest`): sha256 over surface, subject kind/root/`diff_sha`/`tree_sha`, the rules source digest, the checklist layer, the assigned composition (`seat:part` rows), the enforcement, the review-contract fingerprint and the logical round (b); a SETTLED, DISPATCHED ledger record carrying the same key (`review_ledger.find_reusable`, `reuse_or_none`) is returned instead of a wave — `reused=true`, $0 — unless this task's own operation of the round is still open (it is collected first), while a pending record or a `NOT_DISPATCHED` refusal is never reused. The lookup is staged and disclosed: it reads the bounded hot index first (`INDEX_MAX_BYTES`) and opens archived segments only after a hot miss — every new subject is one — newest first and only until the first match; what it read (`rows_read`, `archive_segments` opened) is handed to the caller (`lookup`) and an archive read is logged with those counts. (b) The LOGICAL round (`review_round_sha` → `review_ledger.round_sha_of`) is what the author asked THIS time of these bytes: the `review_rebuttal` content sha, the author questions, the goal and scope as the semantic brief, and the resolved revisions the record names (`base` = parent, `head`) — so a new rebuttal, a changed brief or two revisions of one tree are each one more paid review of the same subject, while the identical request is the settled record. The identical-diff refusal (`commit_gate.check_identical_verdict_refusal`) lets a NEW rebuttal through exactly once, and the paid-cycle ceiling (`check_review_cycles_ceiling`) counts the round and stays COMMON to the root task per `(repo, tool)`: a second subject under an exhausted root is refused, not reset. (c) The RETRY key (`review_retry_key` = `review:<root_key>:<kind>:<diff_sha>:<surface>[:<round_sha[:16]>]`, the round suffix for every parametric wave; the gate's key has none) is the identity of the PHYSICAL operation the custody layer keys attempts by (`review_custody._attempt_key`), set on the context BEFORE any dispatch: a retry of the SAME round rejoins or replays the same physical review and never pays twice, and a NEW round is a new operation — the custody layer never hands a rebuttal the previous round's settled answers. The rejoin is durable (`tools/review_change_custody.py`): the parametric wave's write-ahead paid row carries its reserved roster and checkpoints each delegated start token onto its exact reserved seat (`review_state_custody.checkpoint_pending_review_invocation`, the gate's own write-ahead), its settled row carries the wave's final roster (a seat still owed stays `late_result_pending` with its operation and token), and a rerun of the round on the same task reads the checkout at the same path — one path per task and round (`checkout_token`), so another task's wave of the round never removes it — and finds that attempt row by the retry key (`pending_round_attempt`) BEFORE any reuse lookup, ceiling check or payment and runs the gate's reconcile-only path (`arm_rejoin` → `prepare_frozen_review_reconciliation`: settled seats replay or recover from their durable producer outcomes, the pending seat is rejoined by its exact invocation, nothing new is sent, no second paid row is written, the SAME ledger record is revised) — in this process or after a restart. A wave that fails before it has settled its own custody keeps a checkout an earlier wave retained. The gate's own key, set by its free-cycle gate, is kept when present. Money accounting at dispatch (`paid`) is unchanged by any of the three. The ledger record of a parametric wave names the frozen subject (`subject`: root kind, root, kind, base = parent, head, tree/diff, checkout) and carries `fingerprints.reuse_key` / `fingerprints.retry_key`; `review_ledger.build_wave_record(facts, surface=…)` builds it for every surface, `build_commit_gate_record` is that call on the gate surface. Same head with a different base is a different subject (§10).

#### Change review on any root

`review_change` (`tools/review_change.py`) is the commit gate's reviewer wave without the landing: one subject, at most one paid wave, one review ledger record (`surface="change"`), nothing committed and no test run (`tests.policy=NOT_RUN`; the author attaches verifiable test results separately). The mind calls it by judgment and nothing starts it. It reviews the active workspace (default), the system repository, or a `workspace_root` admitted by the `schedule_subagent` folder policy; the subject (`index`, `worktree`, or `base..head`) is frozen once by the subject operation (`review_subject.freeze_subject`) and, unless it is the body's own staged index against HEAD, read in an isolated checkout of its frozen tree (`isolated_checkout`), so the wave reviews exactly the bytes its record binds. A deterministic call error — `base..head` without both revisions, an unknown subject, a folder that is not a registered readable git root, an unresolvable revision, an empty change — is a typed `TOOL_ARG_ERROR` before any reviewer is paid. The checklist layer follows the root's `body_fact` (`layer_for`): the body is read against the body layer, every other root against the universal core, and `treat_as_body` raises only a root whose body fact is `unknown` (git cannot place it: no remote, no copy binding) to the body layer — a recognized body and a recognized foreign root are unchanged by it, `how` keeps the fact's original value and `detail` records the raise; the record carries `body_fact`/`how`/`treat_as_body`. Composition follows the same fact: on the body outside Cyber Pro the owner's saved rows stand and `reviewers` only adds seats (a named subset is recorded `reviewers_subset_ignored`); on the body in Cyber Pro and on every other subject `reviewers` is the panel (`panel.composition=composed`; omitted, `full_pool` = every configured seat), `reason` is recorded, and a narrowed panel without one records `reason_missing=true` instead of failing. The counted seats of a composed panel are marked pool rows — the owner's menu (decision 1A); an enabled catalog row outside the pool named in `reviewers` is seated as an added critic (`additional`, outside the quorum), and a composition that names no pool seat is a typed `TOOL_ARG_ERROR` before any wave (the preflight's one row stays any enabled row, decision 3A). `commit_reviewed(reviewers=…, reason=…)` composes the commit panel through this same composer (`commit_gate.compose_commit_panel`) under the same rule — the body in Cyber Pro composes, below Cyber Pro the whole pool judges and named rows outside it only add — refused before anything is staged on a bad name or a panel without a pool seat, and the reviewed stage cycle runs under the composed pool exactly as a wave does, so the contract fingerprint, the paid roster, the seat vectors and the gate's record (`composition`, `reason`, `reason_missing`, `reviewers_requested`, `additional`) see the composed seats; no `reviewers` is the configured pool as before (an empty pool stays the gate's own typed `pool_empty` refusal). `coupling_only` critics are seated with `parts=[coupling]` (`review_ledger.seat_parts(row, coupling_only=True)`) and answer only the coupling question, outside the quorum and the recorded verdict; `reviewer_effort` orders this wave's strength; `author_questions` reach the brief and the record verbatim. A composed panel reaches the wave through `reviewer_slot_config.composed_review_pool`, a context-local override (`contextvars.ContextVar`, `_COMPOSED_POOL` over `PoolSeat` rows) that `review_pool_slots` and every pool reader under it see for exactly that wave — the pool threads inherit it through `contextvars.copy_context`, and a concurrent wave on another thread keeps the configured pool. This is a disclosed deviation from the plan-review rule (DEVELOPMENT 06: an envelope `reviewer_effort` is an argument of `plan_review_slots`, never a contextvar): the commit gate's slot readers have no argument path, and growing `review_execution.py` to thread one is out of this operation's bounds — the gate's own cycle enters the same override for a composed `commit_reviewed` panel. The same subject, rules, layer, panel, enforcement, review contract and author questions return the settled record at $0 (`reused=true`); a `review_rebuttal` buys a new wave, and an undecided record is never reused — a rerun of a round whose seat is still owed COLLECTS that operation instead (the subject operation's durable rejoin, above: same checkout, same attempt row, the pending record revised to its verdict, nothing paid twice). Paid waves count against the shared cap per root task and (reviewed repository, `review_change`), apart from the commit gate's count, and the paid attempt row records a review, never a commit; exhaustion is the typed `review_cycles_exhausted` with a `NOT_DISPATCHED` record, and it meets only a NEW paid wave — a reached ceiling never strands an open operation's answer. Enforcement is recorded on every root; only the body under Blocking enforcement records `enforcement_blocks=true`, so another root's FAIL is information, never a lock. `commit_reviewed`/`vcs_commit_reviewed` stay the only landing in the system repository: their `root` accepts only `system_repo`, and any other root is a typed `TOOL_ARG_ERROR` pointing at `review_change` and ordinary git.

#### Review ledger record

`observed_unknown_seats`; `distinct_engines` from `configured_subagents.engine_handle`; `single_model_panel`; `composition` ∈ `full_pool` (every configured seat sat — the commit gate outside Cyber Pro; quorum required/responded/assigned, per-row, `per_question.change` and `per_question.coupling` as the two questions' own answers, findings, degraded reasons), with `author_decision`, `tests`, `preflight`, `dispatch_refusal`, `cost` and the review-contract/binding fingerprints beside it. `review_wave_id` is `review_records.resolve_review_wave` over the gate's retry key, so the record, the usage ledger and the reviewer actor rows name the same wave.

Honesty rules: a `pending` record (custody still open) carries `NOT_PERFORMED` until the SAME attempt settles, which raises the record's `revision` in place — a stale snapshot at the same or a lower revision never overwrites a newer one (`review_projection._keep_newer_producer_facts` precedent). A free refusal before dispatch (`identical_diff_refused`, `review_cycles_exhausted`, pending custody) and a wave the budget fence declined (`review_wave_budget_insufficient`) are `NOT_DISPATCHED` records naming their cause in `dispatch_refusal`; an explicit author continuation buys no record — it notes the author's disposition on the record of the outcome it answered. The record is written on the CANONICAL data root after `parallel_review.run_parallel_review` returns its typed structured result and `aggregate_review_verdict` reads it; the gate decision itself is computed exactly as before and reads nothing from the ledger. Each seat's full brief and raw answer are retained through `artifacts.store_actor_source_bytes` (`task_results/artifacts/<task>/source_handles/context_checkpoints`) BEFORE the record's row is appended to the hot index `state/review_ledger/index.jsonl`; the index is a bounded projection that strips heavy fields only from rows whose record and sources resolve (`review_state_custody._strip_attempt_heavy_payload` precedent), rotates into sibling segments at 2 MB, and carries unresolvable rows forward unstripped (§10 invariant: hot indexes may rotate only after the source is retained). #### Prompt size, density and windows

`review_helpers.REVIEW_PROMPT_TOKEN_BUDGET` bounds assembled inputs: review packets, per-slot plan packets, task-acceptance packets and skill-review chunks with their own headroom. Retrieving seats and deep review assemble briefs, not repository packs; native sends use `review_native_transcript_bound` and reach other sources through tools. Every surface scales its output reserve to the route's usable window (`reviewer_window.window_scaled_reserves`); a reserve sized for a much larger window can otherwise consume all input room before a request reaches the provider.

Sizing is density-calibrated, not keyed to model names. `usage_accounting.execute_physical_attempt` records settled `(prompt_chars, prompt_tokens, route_fp)` witnesses in `capability_evidence.json`. Main uses the newest fresh exact-route witness, then exact-model witness, then neutral density; reviews use the densest fresh exact-model witness, which can undercut `COLD_START_TOKEN_DENSITY`. Stale, absent or cross-model evidence keeps the conservative floor. The witness TTL and bounded retention preserve both its densest support and recent observations. `calibrated_input_token_limit` combines the shared cap, measured density and absolute margin per call; review packet, plan, acceptance and native transcript sizing consume it rather than freezing an import-time result.

Only the review packet has a cold-start probe rung: `review_admission.density_probe_before_size_refusal` invokes `capability_evidence.cold_start_density_probe` when an irreducible packet exceeds a cold route's cap. One bounded slice of the actual prompt is sent on that exact model under `physical_attempt_limit(1)`; its witness buys one resize and fit pass. It never probes a warm route, retries the probe or runs when the packet fits. Progress and `review_density_probe` retain the attempt; a paid-ledger refusal is `budget_refused` and leaves the size refusal unchanged. This breaks the loop in which a request rejected before dispatch can never teach its tokenizer density.

`reviewer_window.resolve_reviewer_window` is the route-specific sizing source, with metadata probes serialized per route and limited by evidence TTL. There is no model-window table or window-authority floor. `ReviewerWindow.sizing_window` has a full-window sizing default for an unknown API window; raw subscription routes keep no numeric unknown-window assumption. `scope_window` adds its designated-default or conservative fallback and distinguishes confirmed, asserted, stale-unverifiable, designated-default and unknown provenance. `POST /api/owner/capability-ack` records an asserted window bound to one route fingerprint, invalidated by a route change; it sizes sends and grants no reviewer authority. A failed send supplies no verdict, while a small window alone does not remove a responding reviewer.

#### The coupling question (Part 2 of the brief)

The commit gate runs ONE wave. Every assigned seat receives one brief by its `parts` (`review_ledger.seat_parts`): a packet seat is asked `[change]` (contract A, the findings array); a retrieving seat — native API or delegated session, in every context mode — is asked `[change, coupling]` (contract B, one object `{change, change_clean, coupling}`); an explicit `coupling_only` critic of `review_change` is asked `[coupling]` and sits outside the quorum. There is one role — the seat — no second wave and no second quorum: `config.adaptive_quorum(len(assigned))` counts the seats that answered at least one asked part once, and `review_ledger.reduce_verdict` decides the aggregate in the gate's order — NOT_DISPATCHED, pending, QUORUM_FAILED, NOT_PERFORMED when no seat answered the coupling question, FAIL on a critical finding of either question, PASS — for the gate and for the durable record alike (`per_question.change` / `per_question.coupling`). A native API seat preserves its configured identity, model, route, account pin, effort, processing preference and local-route flag while the surface selects inspection delivery; a session row uses its configured delegated session.

`review_admission.build_two_part_brief(frozen_subject, seat, *, layer, goal, scope, author_questions)` is the pure builder (`{system, user, parts, sha}`), callable outside the gate; the gate's per-seat path is `retrieving_brief_for_seat` → `review_brief_coupling.build_retrieving_brief`, without dispatch. For the same frozen subject and intent the builder renders the text a wave's seat is sent, byte for byte: the author's questions and the rounds with the checkout's open obligations are rendered by one owner each (`review_prompt_text.goal_with_author_questions`, `review_helpers.review_history_with_obligations`) for the gate, `review_change` and the builder alike, and what a wave reads from its context — the wave label or commit message, the task's rounds, owner words, task evidence, the paging identity — the builder takes as arguments. Part 1 carries intent, rebuttal, history and open obligations; the touched-path dispositions and candidate sizes; the layered Change Review Checklist; task evidence; and the exact staged change. Part 2 carries the `Coupling questions` section of CHECKLISTS, the shared governance tiers, the repository index and the required-source manifest; one anti-pattern guard rides the brief once. Stable governance precedes change-relative context for cache reuse. The full staged diff stays inline while the first send fits, measured by `native_first_send_chars` including schemas and wrapper. Otherwise it becomes one exact paged source in the task artifact store, with a byte-exact `.review-drive` view for a delegated session. An unavailable store is disclosed and keeps the diff inline. Native inline sizing uses the landing threshold within `first_send_bound`; sessions use `SESSION_INLINE_DIFF_CEILING_CHARS` because the harness owns their context selection. A managed-update subject is the authoritative M0→S resolution delta, never a substitute `git diff --cached` over the two-parent candidate. Invalid roots, missing subjects and failed assembly remain typed pre-dispatch failures; only an irreducible first send reaches `native_bound_below_first_send`.

When a seat's brief cannot be built before dispatch, preparation best-effort appends one `review_brief_preparation_failed` row to the existing events log, whose normal sink forwards it live. It names the task, slot, model, the parts asked and the original `context_unavailable` reason. This is seat-local preparation evidence, not a verdict; because the wave is one, the gate blocks the whole wave fail-closed (`infra_failure`) and spends $0. Logging failure preserves the same typed result, and model-control exceptions still propagate before logging.

`scope_required_sources.py` declares the change-relative reading minimum: touched protected runtime, prompts and frozen contracts; protection-owned families (`GIT_OPS_FAMILY_PATHS` and tool-dispatch leaves); and declared Python/browser contract twins, with both sides included. An ordinary touched file needs no whole-body obligation because the diff already carries its complete change. Each readable row binds raw-byte `source_revision`, normalized-text `complete_sha256`/`complete_chars`, range basis and candidate tree. Deleted or renamed sources retain their exact baseline preimages; paged diffs join the same manifest; unavailable sources remain explicit rows. The final rows are shared by brief and policy, and `required_sources_ref` plus `SCOPE_REQUIRED_SOURCES_POLICY` bind the actual manifest and review-contract fingerprint (`commit_gate.commit_review_contract_fingerprint`, which also binds every seat's `parts` and both contracts), so old replay authority cannot survive a changed contract. This minimum never restricts the reviewer's further reading.

Coverage records what could be observed: native receipts match source identity, opened root/path and delivered character intervals; sessions fold weaker journal evidence over the same rows. States are `complete`, `incomplete` with missing ranges, `declared_empty` for an explicitly empty manifest, and `unobserved` when measurement is unavailable. A changed source is a `source_gap`; availability or inline delivery never proves understanding. `review_context_atlas.repository_index` supplies orientation only: compact tracked-path dispositions, collapsed excluded classes, touched-file and direct-importer facts (size, digest, language, symbols and imports, with bounded totals disclosed). It renders no bodies, spends nothing, writes nothing and never limits what the reviewer may open.

The reducer keeps received findings and counts responding seats through `config.adaptive_quorum` independently of coverage. Reading gaps remain seat and wave diagnostics (the seat record's `coverage`, the coupling history's diagnostic line): they cannot change status, block a commit or trigger another paid review. The agent judges whether a particular gap needs more reading. Substantive critical findings still follow `OUROBOROS_REVIEW_ENFORCEMENT`; an unanswered seat does not count, a defective `coupling` block is recorded against that question alone with its error while the seat's `change` answer still counts, and an all-`not_dispatched` wave retains its assembly/admission failure. Oversize requests, route failures and candidate-binding failures never become PASS; budget, custody, deadline and ownership keep their separate contracts. Retrieval keeps the reading obligation proportional to the change while exposing the actual evidence, instead of letting total repository size decide whether review can occur. If the change cannot fit a reviewer, split the change rather than weaken the reviewer.

#### Governance delivery

`tools/governance_context.py` owns the shared tiers for every change-review seat (both parts, on every surface a pool seat serves — the commit gate, `review_change`, the preflight) and for deep review, and takes ONE external switch, the checklist `layer` (`review_body_fact.layer_for`; the governance root is always the installed system repository, whose rules execute). In the **body layer** tier 1 inlines BIBLE.md and CHECKLISTS_ARCHIVE.md, plus the executing code's CHECKLISTS sections: the surface's own and `Shared Contract Ownership`; a proposal cannot replace those rules. Tier 2 selects the review-protocol chapter, DESIGN for `web/` changes and DEVELOPMENT chapters naming touched files, within `runtime_limits.REVIEW_GOVERNANCE_INLINE_SHARE` of the usable window. Tier 3 gives physical-source book navigation for ARCHITECTURE; packet rows may also inline relevant sections within the same share. In the **core layer** (the subject is not the body: another repository) tier 1 is the surface's own universal section alone; BIBLE, the archive, the shared section, DEVELOPMENT, DESIGN and ARCHITECTURE are recorded `not_applicable` and never delivered, and the navigation indexes the SUBJECT's own documents (`subject_root`: root Markdown files and `docs/**`, bounded and disclosed) plus its required-source manifest (`scope_required_sources(..., layer="core")`: empty by rule — the protected-path inventory, prompt rule, families and twins name body files). Each non-inlined document has a manifest disposition and navigation pointer. Retrieving rows can follow those pointers; tool-less packet rows receive an index of material not delivered, never an instruction to call unavailable tools. A whole document with the same source identity is credited `delivered_inline` without another read.

**The body predicate.** `ouroboros/review_body_fact.py` answers ONE question for a change review: is this repository root Ouroboros's body? `body_fact(root, system_repo=..., manifest=..., data_dir=..., treat_as_body=...)` returns `BodyFact(body ∈ {true, false, unknown}, how, detail)`; `layer_for` maps `true` to the body layer and everything else to the core. `how` records the git fact that settled it, in recognition order: `dir` (the root is the system repository or inside it), `git_common_dir` (a worktree or nested copy sharing the body's common git dir, `workspace_copies.source_is_system_repo`), `remote_chain` (a local-path remote reaches the body within three hops), `managed_remote` (a fetch URL equals the install manifest's `managed_remote_url` — the configured update source, official repository or fork), `install_fork` (a fetch URL equals the installed repository's own `origin`), `copy_origin` (the task-owned copy registry binds the root to its source), or `unknown`. URLs compare after normalization (scheme, user info, `.git`, trailing slash, host case); the branch never takes part; no directory, branch or remote NAME is matched by pattern (P5). A remote reaching none of these is `false`; no git, no remote and no copy binding, a git failure or timeout are `unknown` — the review then runs the core with the fact recorded, and the mind may raise `unknown` to `true` with `treat_as_body` (recorded in `detail`; nothing lowers a recognized body). The plan-review `constitutional` fact is the same predicate asked of a declared `affected_paths` locator (below). `review_helpers.checklist_fingerprint(layer)` records which rules ran: the sha256 of the layered text and `rules_source` = `docs/CHECKLISTS.md` at the install's blob (D31: the installed body's rules execute).

### Planning, deep review, reflection, memory

Plan review, task acceptance, commit review and deep self-review answer different questions and never inherit one another's authority: planning judges a proposed approach before implementation, task acceptance the delivered objective, commit review a staged self-change, deep self-review the whole system. Post-task reflection and memory persistence learn from execution but approve none of those boundaries.

#### Plan construction and review

`plan_task` reviews an intention before the work starts, the same organ for code, research, deliverables and actions (BIBLE P3). The obligation is constitutional and the finalization gate structural (`owner_hurry.force_plan_decision`); the order in which a task asks, explores and plans is the mind's judgment. The envelope carries the goal, the plan prose and a typed domain-neutral spec: `in_scope`, `non_goals`, `acceptance_claims`, `invariants`, `decisions`, `deferred`, `affected_paths` (required: the files the work will change, `[]` when none), `affected_resources` (the same question in words, never resolved as paths) and `evidence`. A spec without `affected_paths` is refused before any dispatch (`PLAN_RESOURCE_FORM_REQUIRED`). `ouroboros/tools/plan_spec.py` validates and hashes the full spec and mints the `breaks` targets (`goal`, `claim_N`, `invariant_N`, `decision_N`, `deferred_N`) positionally, because a caller-chosen id could shadow another target. Targets and evidence resolve against the active subject (`active_repo_dir_for`); governance documents always come from the system repository.

One structural fact tiers the governance pack: `constitutional` is true iff a declared `affected_paths` locator resolves under the Ouroboros system repository outside recognized skill-payload roots, whether or not the file exists yet (creating a new file under `ouroboros/` is self-modification). It uses the body predicate’s `dir` relation (`review_body_fact`, Governance delivery); skill payloads stay in the data plane. Nothing else buys the pack: `affected_resources` is prose, and an `evidence` locator is something to look at, because reading a repository file is not changing it. A constitutional plan carries BIBLE.md and ARCHITECTURE.md in full (inline on an `api_chat` row, mandatory full reads on a retrieving `agent_session` row); assembling it without either is a typed failure, not a disclosure. Every other plan carries the heading-derived navigation maps (`context_layout.generate_doc_nav_map`) plus resolvable pointers.

The one caller-facing strength axis is the envelope's optional `reviewer_effort`: an order for this panel that outranks each row's pinned effort (`reviewer_slot_config.row_effort`; a compound Cursor/Agy route slug keeps its encoded effort, which is the route's identity; with no order a row uses its own effort, else the pool's `REVIEW_POOL_DEFAULT_EFFORT`) and reaches `plan_review_slots` only, so other review surfaces keep reading untouched rows. `OUROBOROS_EFFORT_REVIEW` is folded into each row's own effort at load and is inert afterwards, so a plan panel is tuned on its rows. Effort is roster identity: changing it on an open review requires a new panel within the paid-cycle cap. A panel ordered weaker than the owner's setting is disclosed as typed `ordered_weaker` in the verdict text, the Reviews card and the compact index. Under BIBLE P1 this is the panel's strength for one order, never the core's own model, effort or horizon; a cheap panel's closed GREEN is earned authority for that envelope, and a later stronger order does not reopen it.

Declared evidence is resolved by `ouroboros/tools/plan_evidence.py` against two roots only, the active workspace and the system repository, under the shared sensitive-name policy and the bounds `EVIDENCE_PER_ITEM_BYTES` / `EVIDENCE_TOTAL_BYTES`; every refused, missing, truncated, binary or URL locator becomes a typed omission row in the manifest (the host never fetches a URL). A `need_evidence` locator a reviewer names is attached on the next cycle through the same policy; what cannot be attached becomes a `[reviewer-requested]` omission row the panel is dispatched with, never a reason to run no reviewer. The manifest hash joins the spec hash and `constitutional` in the wave fingerprint: changing what reviewers can see changes the identity of the review, while the root's exploration log stays outside it. Every cycle after a paid one continues each reviewer from its exact recorded artifact (a packet slot's transcript when it fits, else a fresh packet disclosed as `capability_delta`; a session slot's sticky thread); the whole panel goes out fresh only when no exact artifact reference exists or the roster changed, and an unreadable referenced artifact fails closed with `plan_review_exact_artifact_unavailable`, never minting replacement authority.

Own-room dialogue is automatic evidence. `ouroboros/dialogue_evidence.py` reads the complete retained room (`Memory.read_chat_generations`, rotated history included, under `project_dialogue.room_membership`), the progress stream and addressed `owner_mailbox` entries. That capture is the snapshot; the inline view a reviewer reads carries the conversation only; gaps stay explicit, and acceptance freshness stays with the acceptance directives ledger. `ouroboros/tools/plan_dialogue.py` stores the redacted room as an immutable `task_source` bound to the author-request identity (goal, prose, spec, declared evidence, the constitutional fact): identical author inputs and free collection reuse it, so room growth cannot buy a new panel, while a changed author request captures the current room. The snapshot digest is part of the fingerprint; `chat:<id>` and `chat:<id>@<sha256>` locators address the room and its snapshots through `plan_evidence.resolve_evidence`, and related Main or lineage rooms remain labelled pointers.

`ouroboros/tools/plan_packet.py` keeps objective, spec and prose complete; own dialogue bypasses ordinary evidence bounds (`plan_dialogue.dialogue_view`, numbered lines reviewers cite as `chat:<id>@<sha256>::lines=A-B`). When a slot's window cannot hold the whole conversation, only dialogue rows yield with the omitted range named, the full snapshot stays reachable, and an oversized immutable core is refused rather than cut; an unknown capacity keeps whole delivery. The snapshot is an observed source (`request_policy.observed_sources`), never a required manifest, and reading coverage never affects parsing, aggregation or cost.

Slots come from `reviewer_slot_config` over the `review_execution._review_route_executor` seam. Reviewers return only a typed findings array: `blocking` with a `breaks` id, `note`, or `need_evidence` with a locator the host attaches (or a spec id as a question to the author). The host validates membership, demotes invalid findings with disclosure, keeps failed slots in the quorum denominator and computes the aggregate through `config.adaptive_quorum`: `DEGRADED` below a parseable quorum, `REVISE_PLAN` when blocking findings reach it, `REVIEW_REQUIRED` while the open set (every unclosed blocking finding and every `need_evidence` without a valid disposition) is non-empty, `GREEN` when a quorum parsed and the open set is empty. Notes never change the verdict, so a note-only wave is GREEN; no reviewer emits GREEN as authority; a reviewer sees the panel's recorded findings but adjudicates only its own, so a neighbour's finding does not vote, and whether to convene children on the intention or call a panel cross-check round is the mind's decision; a claim a reviewer cannot check is a question or a note, never a blocker; premise criticism and simpler alternatives are brainstorming notes whose adoption is Ouroboros's.

`plan_review_state` is the root result's bounded index of waves; full waves, hash-bound specs and evidence manifests stay in artifact custody (`plan_review_artifacts.py`), and authority readers restore them before comparing specs or binding acceptance claims. An unavailable recorded source is an infrastructure failure, never empty claims or an unpaid cycle. The author may select a corrected goal, plan or spec through `review_disposition.author_action`; that subject is kept apart from the critic's wave (`current_attempt.author_subject`), the revised bytes carry no verdict (`plan_review_historical_critic`; tool results publish the critic's real aggregate), and `closed_plan_review_wave` always means critic closure. A wave pins its paid roster, request policy and prepared inputs at dispatch; collection reuses them, never current Settings.

A fresh dispatch returns control at the dispatch barrier (`ReviewRequest.drain_deadline`): the wave is recorded open with typed `pending_dispatch` rows and the workers keep running under process-local custody (`review_custody`). A paid actor still in flight keeps the wave `DEGRADED` with `review_late_result_pending` even when the settled rows meet the quorum, so a late blocking result cannot arrive after a false GREEN. When the last slot settles, one system frame goes into the task's mailbox (`owner_mailbox.write_task_message`) and the mind wakes as for a child result; the settlement never aggregates. Collection is the sole wave writer (`plan_review_collect`): the `review_disposition` mode addressed at the recorded wave reconciles custody at $0 over the wave's own recorded inputs, never re-reading evidence or waiting; it re-records the packet that was physically dispatched, so a directive that arrived after dispatch reaches reviewers only in the next sent packet. A new envelope over an in-flight wave collects what has settled, then supersedes it.

An answer that has not arrived is a gap, never a failure or a verdict. An unanswered slot stays an `ok=False` row no quorum counts; on a same-spec cycle a seat whose absence is terminal keeps its still-open findings from the predecessor, stamped `carried_absent_answer` (`plan_spec.plan_standing_findings`), so silence never manufactures GREEN. The open `DEGRADED` + `custody_pending` pair holds every gate; verdict wording and the task's `degraded` stamp belong to collected slots only. `owner_hurry.force_plan_decision` makes one free collection of the pending wave in every enforcement mode (`plan_review_collect.collect_before_gate`): collection updates disclosed facts, never permission. Context health names an open wave as `PLAN REVIEW WAVE OPEN` without collecting.

Closure follows the finding class over the wave's open set (`plan_spec.closure_after_disposition`, the one closure table). GREEN closes at once in either enforcement mode. Outstanding `need_evidence` closes through a disposition-only `plan_task` call (no model call, no cost; accept, reject, or defer openly). A below-quorum blocking finding closes under advisory enforcement only by a reject with its rationale, because accepting it says the plan is broken and closing it would certify that plan GREEN; under blocking enforcement it stays open until a changed spec is reviewed or the reviewer retires it in a later paid cycle. Closure reads the configured enforcement, not an armed hurry. A `REVIEW_REQUIRED` wave whose open set empties is written GREEN with the note `closed_by_disposition`; `REVISE_PLAN` is never closed by disposition.

Paid cycles are bounded by the shared `OUROBOROS_REVIEW_MAX_CYCLES`; `cycles_paid` and `cycles_exhausted` count paid cycles only. A wave is paid iff a seat was physically dispatched, proved by a settled row, so its paid cycle is recorded at collection, and a wave of `not_dispatched` $0 rows never replaces a paid predecessor. A barrier-dispatched panel is committed money: while its wave is custody-pending and the cap has no room, a revised envelope first collects every other pending wave (`plan_review_collect.collect_before_supersede`) and otherwise is held with the typed `PLAN_REVIEW_IN_FLIGHT` refusal (`plan_review_collect.in_flight_hold`) so the current wave stays collectible. An identical envelope replays free while the wave remains reusable; changed roster or degraded-wave health can require a new panel (`plan_review_runtime.plan_wave_replay_decision`). No host path buys a panel the mind did not send. `plan_review_artifacts.addressed_slots` selects an addressed re-ask from an identical envelope’s `review_disposition` items for a settled, quorum-bearing wave open before the answers, with the current roster: only named slots are re-dispatched; others retain their rows at $0 (`replayed_from`). An escalated question stays open until the mind records its disposition; a quiz answer never closes a finding.

Before fan-out the engine captures one panel health snapshot (`subagents.route_health`): a slot with positive evidence of a spent lane becomes a $0 typed skip row that stays in the denominator; unknown health dispatches. When the wave's own rows prove the quorum structurally unreachable it carries `quorum_unreachable`, and under blocking enforcement the finalization gate releases while the review stays open: the agent may finalize `blocked_with_evidence` (`plan_review_quorum_unreachable`), wait through a one-shot `schedule_followup`, or ask the owner. The host adds facts, never an answer template.

Under blocking an open wave otherwise holds implementation and an exhausted cap escalates as typed `review_cycles_exhausted`. Under advisory the agent may proceed with the wave open after typed owner-visible `plan_review_advisory_open` events, with the open wave recorded in the task's state and result and stated in the agent's own answer. Unavailability, invalid state, budget refusal and deadline rails are typed non-authoritative attempts, never substitutes for GREEN.

#### Deep self-review

The retained report (`memory/deep_review.md`) is historical evidence, not a current-tree verdict: its provenance header records `generated_at`, and `source_revision=unknown` is explicit because a delivery captures no frozen Git revision. Context quotes a disclosed excerpt and leaves the stored report intact.

`/review` is `review_change(subject=system, surface=system)` with one seat: the enabled catalog row the call names (pool member or not), else the direct Main row (`deep_self_review.main_review_row`: Main's model, local flag and pinned account, an empty pin being Auto), so a bare `/review` runs where Main runs. The Web selector (`/review <row>`), a bare `/review` and `request_deep_self_review(reviewer=…)` all queue that name; `queue_deep_self_review_task` refuses a row not enabled in the requester's chat before a worker is held, and the ack, the result and its record link return to that chat. A task with `type=deep_self_review` bypasses the tool loop and calls `review_change.run_system_review`, which re-resolves the row under the task's settings snapshot and runs `deep_self_review.run_deep_self_review` on it. The report is that seat's answer outside the verdict questions, so its one `surface=system` ledger record is never PASS; the record names the chosen seat even on a refusal, binds the live tree snapshotted before the reviewer reads (a tree that moves underneath is the degraded reason `system_tree_moved_during_review`) and carries the call's own `goal`, `author_questions` and `reason` as one `deep_self_review.SystemReviewAsk`, beside the standing questionnaire, never replacing it. Retrieval lets a whole-system survey span successive views while exact sources remain accessible. Every row retrieves, under `ReviewRequest(surface="deep_self_review")` and the shared execution seam, through one of two deliveries:

- **Native inspection**: an `api_chat` row runs `NativeToolRoundReviewExecutor` with the repository root and the real runtime data root, governance inline through the shared tiers; exhaustion returns the retained draft with its incomplete end.
- **Delegated session**: `AgentSessionReviewExecutor` receives the same task and report contract (markdown, not an output schema) and reads through its harness.

Memory is the subject of this review, so both deliveries inline the seven-file whitelist byte-exact (identity, scratchpad, registry, WORLD, full knowledge index, patterns, improvement backlog) and record each file's disposition in the task, in `deep_review_memory` usage and in the report header. Every report carries a sanitized provenance header (delivery, model, memory dispositions, coverage, incomplete status, attestation); reading gaps are diagnostics and never invalidate a finished report. Typed `deep_self_review_unavailable` or `deep_self_review_error` failures return `execution_status=infra_failed` and leave the previous report intact; `BudgetExceeded` propagates to the budget-pause rail. Availability follows `deep_review_route` (an API row needs credentials for its routed model, a session row a healthy delegated route), never a window floor. These reviewers have no mutating tools and run no plan, acceptance or commit reviewers: the report is diagnostic memory, not implementation or publication authority.

#### Post-task reflection

Typed root post-task triggers decide whether a run earns an Experience Review. `reflection.generate_reflection` sends the Light route one open prompt outside the tool loop, records its own usage, and its failure never erases the delivered result or changes a review verdict. The prompt carries the exact initial text with its host-recorded `task_inputs.run_origin` (provenance, not the requirement), the all-calls tool trace (`build_trace_summary(all_calls=True)`; the stored `trace_summary` stays a bounded preview, and values the listing cut are retained and named as optional reading), error, review and child projections, and the bounded plan-review facts (`plan_review_facts.py`: what each finding was, how the author answered, whether the element survived; facts, never a score). Post-task synthesis thinks at the owner's Task effort (`settings_scales.resolve_effort("task")`). Admission to the Pattern Register is typed, not a word scan: a call the loop recorded as errored (`tool_result_code`), a producer fact the ok status cannot carry (a preserved commit whose `post_commit_tests` failed), typed codes already stored, or a genuinely failed child. Children do not reflect, so a short clean root that delegated the work is the only place its child's failure can be learned from; a cancelled, soft-landed or degraded child is not a failure. "A reason code exists" is deliberately not a trigger, because it would open the register on every terminal.

A reflection lands where it durably belongs: a non-project root appends the full entry to the canonical `logs/task_reflections.jsonl`; a project-scoped root writes to its project drive with a bounded pointer row in the canonical log; the Pattern Register update stays canonical. `MEMORY_ACTIONS_JSON` permits only `scratchpad_append`, `knowledge_write` and `identity_update_candidate`, bounded in count and size; `apply_memory_actions` applies them through the provenance-preserving memory and knowledge APIs, and an identity candidate lands in the scratchpad for review, never auto-written to `identity.md`. A project-scoped task applies knowledge actions only, because the conversation writes scratchpad and identity from any room with the full view this Light pass lacks; every skipped action is a `reflection_memory_action_skipped` event with its reason. Reflection may propose a campaign or backlog item, never enqueue, review, commit or enable one. An acceptance panel that settles after its task ended appends one bounded `acceptance_late_settlement` row through the same writer, with no model call, so later tasks read the settled verdict through the recent-reflections window.

The Pattern Register writer (`reflection._update_patterns`) replaces the whole document, so every decision input it reads is complete: the full current register, the exact initial text (`goal_exact`) with its `run_origin`, and the whole reflection text. A prefix of a decision input can never authorize the rewrite, because a clipped clause can record the inverse of what the reflection concluded. `patterns` is a reserved global-only topic beside `improvement-backlog` and `overview`: whichever room writes it, the register has one home on the canonical drive. A register that moved under a losing writer is preserved and that task's learning is dropped with a warning, never retried against a source it did not decide from. A row's count is bumped once per observed episode, not per distinct request.

`review_evidence.collect_review_evidence` projects a task's commit/advisory record for summaries, reflections and the UI: checkout readiness is repository-scoped (any task's edit invalidates coverage), run lists are attributed (`recent_advisory_runs` for this task’s and unknown-owner rows, `foreign_advisory_runs` for other owners), and `stale_marker_provenance` names who wrote a stale marker without filtering it or changing freshness.

Roots own synthesis and children supply evidence; `root_phase_checkpoint` keeps completed stages across Restart. Terminal delivery is at-least-once through the outbox (`supervisor/terminal_delivery.py`, §5); the Project row and its Main mirror are settled by `terminal_projection.settle_terminal_projection` (§3 Main rows and host-stamped card rows); `terminal_time.py` keeps the host-owned per-attempt end time apart from the publication `ts`, never inferred from `ts`, `updated_at` or receiver time, so late evidence is not a new failure.

Synthesis receives a sealed final package from the durable result: the submitted final text, its artifact manifest and `completion_observations`. Full redacted action observations live in the canonical artifact store and are read through `get_task_result(include_completion_source=true)` in explicit ranges after length and hash; references to them are for later readers, not evidence the synthesizer has read. Positive observed facts correct error-trace impressions; tool success does not prove owner receipt, and empty material does not prove absence. Transport delivery reports stay outside the frozen package and never decide admission: a newly written reflection reads them once, after admission, through `presence_delivery.task_delivery_receipts` for the lineage its own walk of the task results finds, inside one captured chat-chain window whose unread older archives make the result nonexhaustive, so absence reads as unobserved, never undelivered. The reports are episodic evidence for one prompt, not a current fact (invariant 10), so they add no store, wait or index. `post_task_synthesis.capture_task_inputs` freezes `review_evidence.task_inputs` (`run_origin`, the owner corpus, question/answer provenance, verification receipts) before context cleanup; the reflection receives them whole. A free `host_task_facts` row precedes the paid stages with no model call. The first paid stage, `memory_fallback_draft` (`memory_fallback.run_fallback_draft`), runs only while consciousness is off: at most one Light draft of one memory unit, billed as consolidation. `files_rescued` counts the files the unmeasured listing finds per store, so no salvageable text never means no files.

Pooled slots persist through post-work, apart from answer delivery; the solve ceiling excludes settled post-work, while Stop, deadline, money, per-call and idle rails bind. `post_task_synthesis.propagate_paid_interruption` owns interruption: owner Pause saves the remainder; budget, other controls or `transport_custody.outcome_unknown_on_chain` skip later paid stages and degrade. Ordinary failures stay local (later stages run, completed reflection actions apply) and end as `degraded`, never `completed`. Startup runs only `pending_once`; an indeterminate `running` degrades without paid replay; `paused` stays held.

#### Project registry and lease

Projects are rooms of one mind (§6 Durable memory and project focus). `projects_registry.py` owns `state/projects.json`: identity and chat, optional folder, lifecycle (`active|deleting|tombstoned`), routing generation/incarnation and activity revision. `project_lease.py` serializes pooled roots per project, not subagent trees, folders, tools or bindings. Delete fences admission, quiesces work, then tombstones; history and data survive.

`project_admission.py` captures execution authority at preparation (`_project_admission`, carried by snapshots and retries); the final committed registry read and the queue append hold queue lock Q together, and the registry stays the only durable authority. Malformed or duplicate identity refuses all execution and writes. A committed witness makes a missing registry unknown to admission, and reconciliation rebuilds eligible rooms as new incarnations, never as old dispatch authority (`docs/PERSISTENCE.md`). Invalid bases or unreadable authority retain accepted rows under a restore hold; bases are never recaptured; release persists before dispatch, and an unknown dispatch stays held as `project_dispatch_unconfirmed`. A refused admission keeps its result and origin notice as `never_admitted` without a completion card. Retries re-admit dispatched work; unknown or missing ancestor results hold children, readable authority permits one start, and missing or unreadable sources hold, never replay (§5).

#### Project binding by task and by origin

Durable bindings outrank task and worker scope, including mid-run (`project_facts.resolve_project_id`). `project_id_for_origin` resolves a captured `(chat_id, client_message_id)`; admission checks exact, predecessor, root, parent and origin bindings before a scope-less enqueue. A known missing room cannot become an unregistered scope. Unreadable bindings refuse pooled Main/API admission, not direct Main dialogue. Conversion, implicit promotion, retry and in-task scoping hold `origin_claim_lock` through lookup and bind. Explicit choices remain autonomous and unrelated tasks never rename a message's room; conflicts refuse before project, lease or broadcast effects (explicit conversion answers 409; one-click adopts the binding); tombstoned ids are not reclaimed. #### In-task project scoping

`ensure_project_scope` (`tools/control_delegation.py`) creates or binds the current root to one project mid-execution: durable registry binding first, then the live queue/lease mark under Q, so the lease counts the running task as a lane occupant. It is idempotent per project; a task bound elsewhere is renamed, not re-scoped (its existing project takes the requested display name; nothing is created). It rides the routing verbs' receipt rail (§6 Task lifecycle) under a synthetic `agent-steer:<token>` id, and its result states only the supervisor's recorded durable outcome: `delivered` with the re-read binding, typed `rejected`, or `unconfirmed` without a receipt in the bounded wait. A project-scoped but unbound run is refused (no durable project to rename); a child cannot escape the inherited scope. A planning obligation stays with the task.

#### Durable memory and project focus

`memory_view.py` renders the memory view for every role from one `ViewSpec`. Block B carries identity and the sealed story of every room: pages and parts dated and placed by their room's own rows at read time (`memory_inventory.record_period`), each page under its host stamp, a correction standing under its record's own words wherever the record is shown and never replacing them. Block C carries the knowledge index, marks, live rooms and the current room with its standing facts in the header (`memory_inventory.room_facts`, `story_counts`), its page, its open conversation verbatim and one host-fact line per task. A page covers a set of rows and an earlier row can stay open, so no sealing frontier is computed. Truncation is not forgetting: only the physical window, or the owner-selected Low/Nano budget, turns host facts, room headers, retold pointers and old pages into addresses, and people's words and Ouroboros's replies become addresses only when the window minus the reply reserve cannot hold them. A subagent's `## Working sources` line is generated from its `ViewSpec`.

`context.py` assembles static governance, semi-stable memory and dynamic task evidence. The recent-activity sections are each task's own newest progress, tool and event rows, read through the bounded rotation-aware reader `jsonl_tail.py` (`Memory.read_task_recent`), never a filtered global tail, because filtering a global tail can starve tasks; each section's coverage line names the rows shown, the window and any unopened archives, and `read_file` pages the rest. Beside its `## Working sources` block, a child reads tools and events from its execution drive and progress from the canonical log. When the rendered scratchpad exceeds `SCRATCHPAD_SECTION_BUDGET_CHARS`, `context.py` keeps the newest whole blocks that fit and drops the oldest behind an in-band gap marker naming `memory/scratchpad.md` as the live source; no context build retires a block. The Development context matrix and `context_layout.py` own which reference form is resident.

**Writers.** A focus seals its own closed matter as a page, over a range of its room's rows, its tasks' rows, or "up to here" (`covers: {to}`: the rows still open up to that address, `memory_inventory.open_room_rows`; coverage, not proof the rows were read); consciousness seals and folds what it judges ready. The host stamps every page with each covered task's recorded outcome: the terminal projection, else the `host_task_facts` row, else the task result, else "not recorded". Only while consciousness is off does the Light helper draft one unit after a root task (the oldest open stretch of a room the view could not hold, a part over records it cannot hold whole, or one period of the earlier retelling re-derived from its rows), signed as the helper's draft and in force until the mind accepts, rejects or corrects it; rows it received only by address stay open, and it never corrects pages or writes the overview. The helper publishes only the trailing JSON object's `text` and verified `quotes`, so prefatory prose and reasoning fields never become the account; there is no tag scrubber or length cap. Light calls share `consolidator.py`'s transport and dispatch binding (`consolidator._light_dispatch_binding`); each scratchpad pass ends in one `scratchpad_consolidation` event. Room labels come from `dialogue_provenance.RoomLabelResolver` on the actual `chat_id`, never a lineage `project_id`.

`knowledge.py` owns note reads, revision-checked writes and indexing; `tools/knowledge.py` exposes them. `knowledge_write(mode="edit", old_str=..., content=...)` replaces one body occurrence under the current revision, frontmatter and other bytes intact, with an optional merged `summary`; a missing or ambiguous anchor, an absent note or a stale revision writes nothing. Automatic writers (scratchpad, reflection) change a note their operation read completely only by anchored `edits` (`{old_text, new_text, basis}` through `compile_anchored_edits`: unique, non-overlapping body spans, atomic) plus an optional `summary`; a new note takes `content`; `knowledge.nomination_write_form` owns the shape and refuses a mixed or malformed one with a typed positional outcome. History rows record the `route` that answered (`knowledge.observed_route_stamp`, read from the returned usage, else `unknown`), never the configured route. The host checks scope, not the basis; backlog and patterns keep their maintainers.

Ouroboros stays one identity across Main, project rooms and Background Consciousness: unified dialogue memory stays available, and an executing project task prefers its own thread, journal, workpad and project knowledge. `project_facts.py` routes project facts to `projects/<id>/knowledge`; subagents inherit the root's resolved project id, never deriving one; identity and scratchpad are one canonical pair written from every room, never copied per project. Project `journal.jsonl` records curated milestones and `workpad.md` the active working context (`tools/project_journal.py`); focused context holds the whole workpad and recent journal rows, pointing visibly to older entries. On root completion only high-signal blockers, questions and interface contracts reach the durable journal from the task-tree ledger. A project digest gives consciousness a concise completion signal, never posing as raw project memory.

### Skills and extensions

Skill capability grows through independent gates, each with its own module: discovery and manifest parsing (`skill_loader.py`, `contracts/skill_manifest.py`), content-hash-bound review (`skill_review.py` / `skill_review_runner.py`), owner grants, dependency reconciliation (`skill_dependencies.py`, `marketplace/isolated_deps.py`), enablement, readiness (`skill_readiness.py`) and execution (`tools/skill_exec.py`). Discovery establishes identity, source, provenance (`.self_authored.json`), conflicts and hash; it confers no trust. Review status, grants, enablement and dependency health stay independent durable facts under `data/state/skills/<name>/`, so a UI toggle, a catalog hash or an old review never becomes execution authority; the gate sequence, payload buckets and marketplace/hub layer are §13's. `skill_readiness_for_execution()` composes review, hash, enablement, grants, dependencies and peer conflicts into phase-specific next actions and reads the mode-aware `gate_for` projection (`executable_review`), never a raw verdict string. The owner may attest their own skill, or a hash-verified official hub payload, to skip the LLM review (`skill_owner_attestation.py`); the deterministic preflight floor still gates it. `list_skills` and the per-turn Installed Skills section project the same live facts as `/api/extensions`. An enablement change appends a best-effort `skill_enabled_changed` event naming the actor; an append failure is logged and never blocks the enablement change. In Cyber, review failures are visible advice; visibility, successful execution and review PASS stay different facts.

A skill may declare a reviewed `presence:` behavior profile: instructions, knowledge topics, runtime defaults and portable capability requests that installation-local selections resolve to exact targets. Admission requires the bound behavior skill installed, enabled, freshly reviewed and complete, then compiles one immutable positive capability ceiling copied through `task_contract`, so mutable skill/Settings state cannot broaden a live turn. An optional owner-local `workspace_root` (`configure_presence` or the Skills settings form; validated by `workspace_admission.validate_workspace_root`, frozen into the task's workspace contract) changes the file/process target while keeping canonical shared memory; it neither derives Project scope nor forks the data drive, and promotion or follow-up tasks keep the admitted folder. A folder that has become unusable refuses the promotion typed (`workspace_unusable`) and writes no chat row. The Presence runner: §12.

`extension_loader.py` and the isolated-dependency layer load only a ready, hash-matching extension — in-process via `PluginAPIImpl`, isolated-dep/native ones as child-process proxies — and a review PASS alone proves neither dependencies installed nor a widget loadable. Per-skill health at `data/state/skills/<name>/health.json` is process-qualified: the server's observation is authoritative, a worker's is a handoff-qualified view.

`skill_lifecycle_queue.py` (§13) exposes queued/running/succeeded/failed plus stale metadata — stale is recovery evidence, not a fake unlock of a still-running thread. Scheduled work is reconciled by `resync_skill_schedules()` and runs only after `skill_readiness_for_execution()` (§5). `skill_payload_binding.resolve_skill_payload_base` fills an omitted skill name or bucket from the selected `TaskConstraint`; explicit selectors still have to resolve to the same physical payload. A selected-skill repair (`skill_repair_admission.py`, §13) is admitted against an immutable `base_content_hash` and verifies the observed `expected_content_hash` before each payload write, advancing it after opaque process work without claiming authorship; drift makes the repair STALE — no long shell lock, no rollback, other writers never blocked.

#### Skill publication

The passive installed-skill projection never launches Betterleaks and never claims the current bytes are publication-ready (`skill_publish_eligibility.py`). Selecting Publish calls `POST /api/skills/{skill}/publish-preflight` (`gateway/skill_publish.py`, read-only), which captures and scans one current payload, recomputes review staleness and returns exactly one backend-authored state (`ready`, `warnings`, `needs_attention`, `repairable`, `hard_block`); the browser only renders it, and only `hard_block` prevents task creation. The authoritative flow is:

`passive index (no scan) → selected preflight → explicit confirmation → ordinary managed task → immutable current capture with separate review provenance → payload scan → GitHub read-only planning → derived-output scans → first GitHub mutation → validated same-skill pull-request receipt → ordinary acceptance`

Publication authority is `skill_publish_eligibility.publication_author_acceptance`: fresh publishable critic authority or qualified current Advisory author authority. Owner attestation alone is not that chain, and catalog hashes and PR receipts never become review PASS. Every outbound byte derives from the capture (`skill_publish_snapshot.py`); the live payload is neither reread nor rehashed to authorize the transaction, so there is no time-of-check/time-of-use drift. Outside Cyber Pro, Betterleaks `high` findings (`skill_publish_scanner.py`) block the outbound call; lower or unknown confidence is a redacted warning; Cyber keeps scanner and review results as independent advice. Packaged installs resolve the bundled `betterleaks-standalone`; a source checkout installs the managed runtime explicitly with `python -m ouroboros.betterleaks_runtime install` — Publish never downloads it. A `skill_publish` task (`tools/skill_publish.py`) is accepted only when its pre-truncation metadata holds a validated pull-request receipt for the requested skill and configured Hub repository; the receipt proves the observed publication and never manufactures review PASS. A failed envelope (`skill_publish_result.py`) names the failed stage (`reason_code`), a `repair_hint` and the transport's sanitized `error_detail`.

Owner lifecycle actions share `skill_lifecycle_actions.run_skill_action`: grant/toggle run in the lifecycle lane, local delete uses `skill_uninstall_state`, and attestation keeps its deterministic floor. The host supplies actor identity and checks exact resource/revision plus an existing chat message, answered quiz or owner-mailbox record when owner intent is needed; the model interprets that source. A generated edit-and-review request confers no grant, attestation, deletion or enable authority: a client `allow_enable` flag authorizes nothing, Presence ceilings come first, a newer owner disable in `enabled.json` wins, and a Repair review never auto-enables — the model chooses `toggle_skill`. There is no permission ledger and no HTTP impersonation; the auto-grant policy stays separate from enablement, and an explicit owner disable survives review and free replay. `skill_exec` returns the revision captured before its script launch, and extension tool receipts carry the descriptor's `content_hash` only after physical dispatch; neither is review PASS or a semantic test verdict. Marketplace update, adopt rollback (`install.PayloadRollbackSnapshot`) and the publication-record owner (`marketplace/provenance.py`): §13.

### MCP and browser-facing external tools

`mcp_client.py` owns configured HTTP/SSE and local stdio MCP discovery and invocation (HTTP surface `gateway/mcp.py`; tools are named `mcp_<server>__<tool>`). HTTP/SSE entries validate URLs and auth headers, URL userinfo is masked through the shared secret projection (`secret_masking.py` owns the MCP token placeholder shapes), and nested MCP secret values never migrate silently. Stdio entries pass one executable `command` and an exact string `args` list to the MCP SDK without a shell; optional `cwd`, literal `env` and `env_from_settings` (environment name → existing setting key) resolve from the same saved configuration for discovery and calls. Unknown fields are retained with a visible not-applied warning while a valid server stays usable; invalid known fields produce `MCP_CONFIG_ERROR`. Discovered tools join the selected initial capability envelope beside enabled, granted extension tools, behind the same `network` resource gate as on a managed task, and a discovery failure is an explicit capability omission through `list_available_tools`, never a silent removal. The catalog lookup (`MCPManager.resolve_tool_name`) precedes the paid safety check: an unlisted, disabled or, outside Cyber Pro, allowlisted-out tool is refused typed (`UNKNOWN_TOOL`, `MCP_UNAVAILABLE`, `ACCESS_BLOCKED`) without safety, transport or a refresh, and a hit rechecks settings before Safety to honor revocation. Descriptions and results remain untrusted data; every call still crosses registry, resource, safety, timeout and result-handling policy. `web=false` alone does not disable configured MCP or extensions; explicit `network=false` and tool disables are enforced at discovery and dispatch.

Browser tools are stateful and thread-sticky because Playwright sessions and greenlets have thread affinity; they cannot be scheduled as ordinary parallel stateless calls. A stateful-tool timeout therefore retires the browser generation: the shared `browser_state` slot is replaced and the close runs on the owning thread once the hung call settles. Retired sessions are bounded per task at `_RETIRED_GENERATIONS_MAX`, after which another session is a typed `BROWSER_BACKLOG_RETIRED_SESSIONS` refusal; generation isolation is best-effort under concurrent replacement (a fully closed class needs a process-isolated browser worker). In-page evaluation races the supplied expression against an in-page rejection (`_evaluate_bounded`); the outer tool timeout remains the backstop. Chromium is the default; WebKit and device descriptors are targeted tools for a real Safari/iOS risk, not a universal acceptance matrix.

Browser target policy is `browser_policy.py`: owner-control admission uses the actual HTTP request and three-valued service identity — never JavaScript substring guesses, no per-request LLM, no second policy engine. Cyber root/acting requests retain target and control reach; explicit read-only assignments keep their restricted contract. A live binding in `state/server_port.bindings.json` proves an endpoint ours; recorded expectations (`state/server_port`, `state/server_process.json`, the Host Service configuration, the local model's custody row) name what is expected, and a matching expected endpoint whose process cannot be verified is refused as unknown, never treated as foreign (`server_process.runtime_service_identity`). Every other port is an ordinary target, an unrelated application reusing an `/api/owner/...` pathname included; a restricted target that DNS cannot classify is a typed `BROWSER_POLICY_UNAVAILABLE` refusal before navigation. Browsers follow HTTP redirects natively and route callbacks see only the first URL of a chain, so `tools/browser.py` re-checks each document's `redirected_from` chain with the same target predicate before any page result: an allowed→blocked→allowed redirect withholds its content and refuses actions on that document, while the forbidden hop's request has already been dispatched — a disclosed residual, not a pre-request or DNS-rebinding guarantee. Cookies, POST semantics, service workers and native redirects are untouched: no proxy, CDP fork, pre-probe or refetch.

### Budget tracking

`usage_accounting.py` owns monetary policy over physical attempts: `reserved → dispatched → settled | unresolved`, or pre-dispatch `reserved → released`. Only typed engine proof of no complete inference request permits `dispatched → released`; full handoff, timeout and unobserved transport stay unresolved. Retries get new attempt ids; SDK/stream boundaries are labelled opaque. Every model-calling lane is covered and root scopes count tree and post-task/review work once; credential-bearing external scripts and extensions remain unknown/unmetered at host-observed opaque boundaries. A proven abandoned send closes administratively as `settled` with `settle_reason="abandoned"`, `cost_usd=None` and `cost_final=false`: its reservation bound stays unresolved exposure, not known spend; a real late receipt may correct the same attempt once (`late_receipt`). Other terminal settlements and releases are immutable ([Usage store](../USAGE_STORE.md)).

`cost_projection.py` owns producer amounts and openness: `accounted_upper_bound_usd` = settled+reserved+unresolved, null is unknown, finality is never invented, and `COST_OPENNESS_FIELDS` accompanies amounts. `cost_presentation` binds amount and facts to one bucket (§11.1): `reconstruct_task_cost` owns the own scope; root terminal, heartbeat, checkpoint and synthesis paths use root-tree and never fall from a null subtree to own zero. A price or retained bound evidences zero; empty or unpriced rows do not; unknown never becomes sticky-final. Summary, reflection and consolidation share a frozen ledger snapshot; the final terminal checkpoint alone owns final cost, and a read failure is unavailable/null, never zero. `terminal_cost_reconciliation` settles open attempts after the task from receipts first, then owned-engine HTTP, keeping late-receipt rights; `root_phase_checkpoint.accounting` retains the cumulative ledger observation, explicitly null on failure; neither proves an invoice. Unknown spend remains the `unknown_unmetered` field, not a third accounting status. The pacing checkpoints carry `resource_facts` (tool counts, producer-reported durations, ledger buckets, the unreserved global remainder); prompt and checkpoint show the same facts, and no argv, stdout or sleep/poll classification selects behavior. `swarm_efficiency.fanout_count` and `fanout_interval_sec_total` count observed fan-out emissions and the wall-clock gaps between them; neither infers work waves or child-wait time.

**Planning threshold** (`task_pacing.py`). One unreserved `CostCeiling` (`disabled`, `active`, `exhausted_soft_land`, `unknown`) owns runtime `in_task_cost_ceiling` disclosure and loop checks. An ordinary task has none (`no_default_cost_stop`): only an explicit `cost_hard_stop_pct` sets min(global-remainder share, root cap minus margin), and a producer allowance (a wake's remainder) stops at its actual value. Descendants inherit the root's number under its authority, re-read by `restore_cost_ceiling` at every cold restore; an unreadable root keeps the number as `legacy_policy_unverified`, never widened. Monetary admission stays independent. `loop_budget._check_budget_limits` runs after unfinished spending rounds, tool and no-tool alike; no-tool tails (cold Resume's `resume_point.budget_tail` included) neither advance nanny baselines nor arm tool controls, and READY returns before this check without an extra paid final. Eligible actors pause, even before work on a soft threshold; ineligible actors at an explicit profile's stop keep the priced terminal rail (`budget_wrapup_unaffordable` if it cannot fit), whose send still meets the known-spend fence, so a reached cap buys no recap; at a producer allowance or an unverified number, which the fence never checks, the host notice ends them unpaid. Affordability probes (explicit profiles only) reserve nothing; full-cap ledger admission on known spend decides. Unknown spend is not zero; unknown price fails open. `_usage_cache_splits.py` reuses settled cache splits per provider, route and review surface for reservation; `task_pacing.main_loop_wire_options` owns wire options with no later payload additions, and identity drift refuses pre-send (`forced_candidate_drift`) while terminal handling retries once unpredicated, still ledger-priced, so drift cannot lose the answer.

#### Exact budget pause and Resume

`budget_pause.py` pauses pooled and direct work under the same task id on global exhaustion, graceful ceiling, either last-fit stop, soft landing or refused dispatch, without a paid final; a missing task id, root or continuation owner keeps terminal behavior (`exact_pause_unavailable`). Increases never wake tasks. Each step is durable before the next:

| Owner | Contract |
|---|---|
| `request_pause`, `usage_accounting.reserve_attempt` | Close the dispatch fence (`DispatchFenced`; review sends and Light extraction refuse too) and persist `pausing` before waiting, so crash custody cannot replay ambiguous work; the reaper derives its crash-retry fence from that row (`worker_health._complete_exact_budget_pause_after_death`). |
| `local_producer_observation`, `observe_task_runs` | Hold the worker nonterminal until sent reviews settle through `review_custody` and late tool futures settle; a failed publication holds (`budget_pause_hold`) and never buys a final; only Stop/Panic/deadline/cancel ends the hold, as `abandoned`. Unsettled delegated runs get `cancel_and_verify`, because pre-terminal subscription coverage is unproven and an unknown stop permits no second writer. |
| `owner_wait.continuation_state` | Retain cognition, opaque acceptance/preparation and usage/rounds/clocks; `resume_point` keeps the budget tail and unanswered call ids, so Resume inserts execution-UNKNOWN host rows and never replays tools. |
| `events_budget.install_exact_budget_pause` | Park RUNNING or `parkable_direct_task` work in PENDING as `_budget_pause`, persist the snapshot, then mark `paused`; a root scope fences the tree, and a live-pause canonical row outranks replicas and the queue mirror (`task_status.effective_task_result`). |
| `worker_health`, `queue_snapshot._park_pausing_running_rows`, `workers.kill_workers`, `budget_pause_restore_refusal` | Complete or re-park a saved pause after death, shutdown or restart, never `pending_parent_interrupted`; a pause that cannot be restored stays under `_budget_pause_hold`, never dropped or cancelled. |

**Loop grant.** `POST /api/tasks/{id}/resume` → `queue_transitions.resume_budget_paused_task` → `budget_resume.grant_exact_budget_resume`: it requires positive global/root headroom from a fresh strict ledger read (`refresh_root_accounting`, `usage_admission.task_money_snapshot`; a cached snapshot, an unreadable ledger or a degraded tree refuses typed, while display readers keep a bounded-stale fallback), clear cancel/restart/Panic/deadline/lifetime rails and an unpaused ancestor root. Pause id/generation and `resume_generation` bind a single-use grant; `revoke_exact_budget_resume` re-parks after lost money or restart. `model_wait.execution_elapsed_seconds` subtracts quota unions and cumulative paused time from the original `started_at` across continuations; money, round and review wallets never reset.

**Descendant selection.** `events_budget.hold_root_resume_descendants` makes children eligible, not runnable: exact rows stay paused, fence-only siblings get `root_fence_lifted_pending_selection`. `resume_child_task` (event `budget_resume_child`, recorded `selected_by`) selects within lineage — a root selects stored descendants, an intermediate parent only direct children — and `budget_pause.budget_fence_selected` binds one member to its fence generation through assignment, launch handoff and `reserve_attempt`. Unselected, held and re-paused rows stay fenced; a new root pause invalidates pending child grants; other roots and terminal members never revive. The grant binds the queue row's `root_task_id`, never a saved pause's own root field.

**Consumption.** `resume_paused_loop` rejects spent, revoked or foreign grants and discloses drift and custody before effects; a consumption publication that fails holds (`resume_grant_consumption_unwritable`), never FAILED. Graceful Resume of an explicit profile admits one fitting reservation from the same strict tree read (`_second_reservation_fits`, `budget_resume_last_fit_admitted`), avoiding an early-margin re-pause; a producer allowance (`producer_allowance_not_expanded`), an unverified number (`policy_unverified_not_expanded`) or a disabled ceiling is never widened or re-armed, and the notice says the launch allowance still binds; hard exhaustion needs an owner increase. Browser, services, hidden state and crash recovery are not restored.

#### The model's own sleep

`await_messages` defaults to bounded `mode=in_slot`/`timeout_sec`. The model chooses `warm` or `cold`, without a duration threshold. Selectors name exact senders, task or delegated-run terminals, the exit of the task's own `services` (warm only) and optional `wake_at`/`wake_after_sec`; with no selector, any addressed mail wakes it, and owner words and controls bypass filters. Canonical read → install wait → recheck prevents lost wakes; a terminal wake means settled, never success. A `services` selector pins each name to the start it has now (`service_id`, `started_at`, `backend_pid`) and reads execution facts only (`tools/services.service_execution_facts`): an exit wakes `service:<name>:exited:<code>` with the real return code where available (`unknown` for Docker); a start this process has lost, an unreadable record or an inconclusive probe wakes `service:<name>:unknown` for the model to judge — never success. Cold sleep refuses the selector before parking, because its process holds the services.

| Mode | Capacity, custody and wake |
|---|---|
| Warm | `wait_after_tools` saves owner-wait `reason=sleep` and selectors. Pooled work lends capacity but retains the project lane; direct work retains its actor. A queued root needing that lane cannot be its wake source. Resume reacquires capacity and rechecks controls and writer admission. |
| Cold | `cold_blockers` includes root and tree claims, runs, services, processes and running children; only the current sleep-tool invocation is exempt. The `budget_pause` seed (rail `model_sleep`, reason `sleep`) closes subtree launch admission before the final census; a dependency found after the seed abandons only that seed (`cold_sleep_dependency_blocked`), cancelling nothing. `sleep_wake.py` observes readiness off-lock, records `sleep_ready`, then `grant_exact_sleep_resume` validates identity and every hold, owner Pause, money, deadline, lifetime and custody veto. General Resume cannot impersonate `sleep_wake`. |

Sleep time is excluded from execution time: warm exclusion is live (`TaskModelWait.sleep_started_monotonic`) and folded once into paused time; cold handoffs add `sleep_exclusion_since` at grant, removed by the reducer on consumption; hard `deadline_at` never moves. Manual Restart retains a current-attempt, hash-validated warm sleep by transferring it into the exact pause (`set_budget_pause(expected_owner_wait=...)`); a retained sleep always needs explicit Resume before automatic wake.

#### Owner Pause of a whole tree

`POST /api/tasks/{id}/pause` accepts a live root with text-free `{request_id}`; Cancel/Stop still veto. Its durable `owner_pause` fence precedes acknowledgement, then the queue `cause=owner_pause` latch (enqueue refuses `root_owner_paused`); a busy launch lock answers 202 `latch_pending`, and the same id completes it. Each live member gets one `owner_pause` control (ACKed `owner_pause_wake`) and parks via the exact pause (reason `owner`, rail `owner_pause`); started work settles uncancelled. Request history survives Resume and new generations: a late replay returns its released fence unlatched, and new actions need new ids. Post-task Resume reassesses inputs (`post_task_checkpoint.py`); Pause-bound unsent acceptance survives controller death for explicit Resume (`review_operation.py`). Money/deadline gates and paid/unknown custody still bind.

A confirmed launch handoff excludes an accepted Pause: a raw model send after preparation/accounting, a loop tool once the registry joins its handler worker (browser tools consume one-use tickets on their sticky executor), a worker or session once durable `admitted_dispatch=possible` (schedule receipts `dispatch=possible`) and the RUNNING mirror precede the gated queue put — unknown never becomes unsent. Locks cover submission, never completion or network waits; claims prove no handoff. `run_tool_handler` records actual unwind/join regardless of business outcome, and `tool_custody.py` projects surviving invocation, supervisor receipt and merge ownership for Pause, Continue and cold sleep. A root join proves no escaped-descendant or remote-effect settlement, the same residual as exit 0; only proven unentered tasks release paid attempts.

Unreadable fence or member-sleep authority refuses typed (`owner_pause_authority_unreadable`, `model_sleep_authority_unreadable`); a member whose launch authority is unavailable (`owner_launch_authority_unavailable`) retries at the fixed `_HOLD_POLL_SEC` poll, normalizing no-start to `ModelWaitInterrupted`. Live runs keep saved checkpoints `pausing` (`external_writers_running`); fresh observation yields `paused` only without running members or unsettled sent work. Root Resume rechecks whole-tree effect custody at the canonical budget root, binding the observed owner fence to its grant; unsettled or unreadable custody refuses. Exact-grant consumption opens that fence unless a newer Pause supersedes it; queued roots resume by explicit selection; a restored owner marker's latch is its queue root's durable fence, lifted only by the root's Resume. Related schedule Restore uses its exact pause control identity (`followup_released`), never auto-release, fan-out or adopt.

#### Owner Continue after a technical interruption

Continue admits a new root in the same room/folder, reads interrupted work and leaves old helpers paused, adopting none. Its room is the predecessor's canonical Project binding, never a stale row copy. Owner Stop/Panic and author finish stay final. The successor judges and asks in the existing conversation, without a date/budget form.

| Step | Authority |
|---|---|
| Identity/replay | `successor_id(predecessor, action_nonce)` names one action; clients retain the nonce, a `bound` offer restores it after reload, and only `admitted` names confirmed admission. The complete frozen binding (`binding_sha256`) is compared, not just the id: `_replay` returns the same successor in any state or refuses `continuation_identity_conflict`; another nonce returns `already_continued`. |
| Eligibility/claim | `continuation_eligibility` consumes typed interruption facts, never prose: live, non-root or unrecorded causes, owner Stop, Panic, hard deadline/money and author finish refuse; worker crash and completed technical rails are eligible. `claim_on_predecessor` writes locked `continued_by` before effects. |
| Sources | Exact `origin_message_text` and later owner words (ACKed or unread) are kept across chains; the predecessor's `get_task_result` is an agent note and task mail is peer context (`objective_author.kind=continuation`/`owner_corpus`, never the composed work order). Incomplete sources refuse `owner_source_missing`. |
| Admission | The existing `reserve_task_admission` token; under the queue lock a prepared non-dispatchable row and result `continuation_admission`, then the committed snapshot (`_continuation_prepared` survives partial publication). It carries the hard `deadline_at`, the original billing group and the predecessor root's explicit `reasoning_effort`. |
| Writers | `conflicting_writers` (the predecessor's open or paused late work, dispatchable members, retained delegated runs, tool/model invocations, owned processes/services, control/merge receipts, unreadable custody) hold the same action as `continuation_writer_unsettled` — no diagnostic successor, second writer or timeout release. Owner Resume and `release_settled_continuations` recheck custody (`predecessor_writers_unsettled`); a newer Restart hold wins. |

`tree_member_results` selects retained members through `task_result_facts.raw_result_facts`, then strictly rereads authority; unreadable membership blocks. Raw sends and tool claims bind `TaskModelWait` task/attempt/pid/process birth; pool kill, cancel, timeout and crash recovery move matching invocations into `retired_tool_invocations` (visible in `get_task_result`): unknown effects, no replay, money unresolved for late receipts. Automatic release and manual `resume_budget_paused_task` snapshot candidate, holds, fences and root grant under the queue lock, observe predecessor custody and money outside it, then revalidate identity and authority before selection; changed or unreadable authority stays held, and selection needs `admitted_dispatch=none` or a positive `paused_before_dispatch`. Occurrence/token, the frozen receipt `dispatch=possible`, the live queue row `admitted_dispatch=possible` and owner holds bind; unknown dispatch stays held. Review waits and slot deadlines belong to paid operations, outside the author lifetime: Pause blocks new sends while SENT settles, and collection buys nothing.

#### Monetary authority and projections

**Live global limit.** One agent resolver reads saved settings, reparsed on change; a failure falls back to the environment without caching the failure. Workers refresh the environment at task start, and live file reads keep reservation/wallet `TOTAL_BUDGET` current; planning thresholds stay separate. Absent means the shipped default; non-positive means unbounded, silencing the loop's global axis. A run cap set by a launcher before settings load (`OUROBOROS_REVIEW_RUN_CAP_USD`, the isolated contributor review only) replaces the saved budget for that process tree, whose ledger starts empty; an unreadable cap is a zero allowance.

`pricing.py` uses bounded best-effort exact normalized-route catalog lookup, never manual tables, prefix/fallback prices or admission allowlists. Every limit refuses once known (settled) spend reaches it, at reserve and again at dispatch; holds and unresolved bounds are exposure, never spending, so concurrent or late charges can overshoot. Unknown price: reserve None, settle the reported cost or a later exact price, otherwise None/non-final. Only structural pre-generation evidence with zero usage permits confirmed-zero rejection or release. `usage_admission.review_wave_admission` admits a skill, plan, task or commit wave while known spend is below every global/root/group limit; the shared estimator's wave total is disclosure, and a managed update only records it (`managed_update_wave_estimate`); unpayable slots bypass without substitution, and unknown prices stay disclosed without disabling priced siblings.

**Whole-work billing group.** `usage_admission.py` keeps task/root/parent ids distinct from `billing_group_id`/`billing_group_limit_usd`; one store transaction checks global, root and group, successors and original-root late work included. Continue carries the initial `billing_group`, else the earliest live ledger authority, else the configured cap (`legacy_default`); `BindingIndex` keeps unlimited `None`, and the store keeps each binding ([store](../USAGE_STORE.md)). Review-wave `binding_axis=group`, pacing and strict Resume share this authority; only the group owner amends its cap, and `task_money_snapshot` keeps distinct root/group axes over shared spend. A rootless descendant refuses; late overruns bar admission without a bill guarantee; standalone UI/marketplace contexts declare a non-task role. Reservations retain the applied `global_limit_usd`, explicit unbounded state and `global_limit_source`/`global_limit_revision` through transitions; money is decimal text summed with `Decimal` in the writing transaction, because six-decimal display rounding is not monetary equality. `_usage_money` owns exact cash and admission rounding; `_usage_wait` retries pre-send contention and joins async mutation.

For roots, `GET /api/tasks/{id}` derives `cost_breakdown` from the store (own/child/unattributed/delegated costs, subscription sessions, unknowns, finality, authority); it is never persisted and never a third sum, and an unreadable or unattributable ledger omits it rather than asserting zero. Review emits one `llm_usage` per physical send with wave/slot attribution (`review_records.resolve_review_wave`); `skill_review_usage.py` projects `(review_skill, review_wave_id)` without another ledger; delegated rows report their own route provider and resolved model, never inferred values. `state.json`, task results, `llm_usage`, `/api/state` and `/api/cost-breakdown` are compatibility projections. The store's one-time import takes pre-ledger usage once, with source hashes, disclosing ambiguity without log rewrites or invented attempts.
